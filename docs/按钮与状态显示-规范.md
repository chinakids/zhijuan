# 按钮与状态显示 · 统一规范（2026-09-17 主人拍板）

> 主人（2026-09-17，F-20260916-07/08）：① 按钮是否带文本要有统一规范——**关键行动点的按钮需要文字，功能点按钮可以把文字收进 tip**；有些地方一排按钮把字挤压没了。② **状态不要用「括号+数字」**（如「（7 处问题）」「（其中 1 条严重度变化）」）——直接用角标（badge）。
> 本文档=织卷 UI 按钮与状态显示的强制规范；体验层走查与设计系统评审均以此为准，冲突时以本文档为准并回改。

## 一、按钮文本分级（按钮必须落在这三级之一）

| 级别 | 定义 | 文本策略 | 实例（织卷） |
|---|---|---|---|
| **① 关键行动点** | 每页/每流程的主 CTA、产生不可逆或重要动作的按钮 | **必须有文字**（可带 icon；icon 不替代文字） | 保存、采纳并写入、接受、拒绝、提交、重新体检（状态栏）[…] |
| **② 常规行动** | 次级但语义明确的动作 | 图标+文字 或 纯文字；**同一排最多保留 1-2 个带文字按钮**，其余降级 | 让 agent 改、转提案、重试、清除、与上次对比 |
| **③ 功能点** | 高频工具/轻量操作，语义靠图标即可 | **纯图标 + tooltip**（`title`+`aria-label` 双写）；禁止塞文字 | 检查 ▾、清空对话、刷新、×、折叠/展开、拖动条 |

### 一排按钮的排布规则（防文字被挤压）
1. 带文字按钮一律 `shrink-0 whitespace-nowrap`——文字永远完整，空间不足时**换行**而非挤压（`flex-wrap` 兜底）；
2. 纯 icon 按钮同排成组、组间用分隔/间距；同排 icon 尺寸一致（紧凑 12px / 常规 14px）；
3. 一排按钮总数 ≤4（含 icon 组）：超出部分收进「⋯」更多菜单 或 转功能点+tip；
4. 同一行内**不允许出现第 3 个带文字按钮**；破坏此规则时按上表降级（常规→功能点）或换行。

## 二、状态显示规范（角标优先）
1. **状态计数/数字一律用角标（badge）**：图标右上角小圆徽（≤99 显示数字，>99 显示 99+）或行内 pill（如「严重度变化 1」）；**禁止写成「（N …）」括号文本**；
2. 状态文案**不用括号**；tooltip 也不用括号，用「·」或「。」分隔（如「规则体检：7 处问题 · 人物在场 1、正文缺段 2 · 点击查看详情」）；
3. 占位/途中文案不用括号（如「正在思考…」而非「（正在思考…）」）；括号仅用于补充说明性引用（如代码、原文）时豁免。

## 三、已执行实例（2026-09-17）
- HealthBar：问题数从「规则体检：7 处问题」文本改为**盾牌右上角琥珀角标数字**，文案收敛为「规则体检：有问题/无问题」，明细进 tooltip（去括号）；
- AuditDrawer「与上次对比」：「（其中 1 条严重度变化）」→ 行内 **pill 徽标「严重度变化 1」**；
- AgentPanel 折叠脑内过程占位：「（正在思考…）」→「正在思考…」；
- ProposalDrawer 接受/拒绝/清除：补 `shrink-0 whitespace-nowrap`（防窄抽屉挤压）。
