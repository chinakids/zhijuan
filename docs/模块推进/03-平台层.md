### 2026-09-10 02:32–03:05（第 3 轮：候选 1 打包分发 .app 可行性规划）

**① 调研**（r.jina.ai 直连抓取；本机 web_search/searxng 全引擎仍挂起）：
- electron-vite Distribution https://electron-vite.org/guide/distribution ：ASAR 限制——`child_process.exec/spawn` **不能执行作为参数出现的 asar 内路径**；原生模块（*.node/.app/.exe）不应打进 asar；官方 electron-builder.yml 示例（files 白名单 + asarUnpack + afterSign）。
- electron-builder File Patterns https://www.electron.build/docs/contents ：files/extraResources/asar/npmRebuild 语义；**production dependencies 默认自动进包**（靠移 devDependencies 规避）。
- Electron 官方 ASAR tutorial https://www.electronjs.org/docs/latest/tutorial/asar-archives ：asar 只读；**cwd 不能设为 asar 内目录**；execFile/fs.open/process.dlopen 走临时解包；spawn/exec 仅支持包外真路径；Electron 31.x 已 EOL。
- Electron 31 release blog https://www.electronjs.org/blog/electron-31-0 ：31.x = Chromium 126 / V8 12.6 / **Node 20.14.0**（决定兜底 node 的版本口径）。
- 本机实证（只读命令）：`out/main/index.js` 仅 128KB、require 只有内建模块+electron ⇒ **主进程被 electron-vite 全量 bundle，运行时零 npm 依赖**；out/preload 仅 require('electron')（同理）；`dsh-runtime` 273MB（200 个 @deepseek-ai 包；原生模块：node-pty 跨平台 prebuilds 23MB 其中 darwin-arm64 仅 140KB、sharp 仅 darwin-arm64、node-addon-require-builtin 仅 darwin-arm64）；宿主机 arm64、系统 node v24.19.0；dshhome 8.6MB（profiles/*.yml 被 git 跟踪）、run/ 4KB（patch 运行期写入）。

**② 规划**（结论：**可行，无不可逆；定位=内部自用分发，不做签名/商店/自动更新**）：
- **形态**：electron-builder（devDep，构建期工具不违红线）+ 单包结构，`asar: true` 保留（主/预/渲染全 bundle、无外部资源）；**dsh-runtime 必须走 `extraResources` 出 asar**——子进程是独立真 node、无 Electron 的 asar fs patch，且含 .node 原生模块（dlopen 需真路径）、cwd 需设为运行时根；`asarUnpack` 不够（路径仍在 app.asar 命名空间内，子进程解析不到 unpacked 真路径）。访问侧 `runtimeDir()` 加 `app.isPackaged` 分支 → `join(process.resourcesPath,'dsh-runtime')`（dev 行为不变）。
- **节点宿主（无 node 的目标机）**：方案 A=extraResources 带官方 node 二进制（+~60MB 解压）；**方案 B（推荐起步）= `process.execPath` + env `ELECTRON_RUN_AS_NODE=1`**（0 额外体积；Electron 31 内嵌 Node 20.14.0；需真机冒烟确认 dsh 依赖树（按 node 24 安装）在 20.14 下可跑——sharp 0.35 要求 ≥18.17、node-pty 为 N-API，预期兼容，属实施轮判据）。现有 nodeBin() 的“Electron 兜底吞输出”坑＝缺 RUN_AS_NODE env 所致，实施时一起修。
- **可写状态分离**：打包后 `dsh-runtime/dshhome`（8.6MB，含生成物）与 `run/*.patch.yml`（主进程每启动重写）若留在 .app 内既不干净也不抗重装/升级 → 实施轮拍板：仅 `app.isPackaged` 时将 dshHome 与 run 迁 `app.getPath('userData')` 下（`<userData>/dshhome`、`<userData>/run`），dev 保持现状；首启幂等（现有 mkdir/写入逻辑已幂等，只需移目录常量）。
- **包体与裁剪**：files 白名单仅 `out/**`+`package.json`；**dependencies 全部移 devDependencies**（构建期需要，运行期 bundler 已内联；dsh-runtime 是独立 vendored 树不受影响）；extraResources 的 filter 剔 `node-pty/prebuilds/{win32,linux}*`（省 23MB）与 `dshhome` 内生成物、`.git`、tsconfig 等；`electronLanguages` 只留 zh-CN/en。预估 .app ≈ 500MB、zip≈250MB。
- **不做**：notarization/签名（内部自用，首启右键打开+xattr -cr 足够）、Windows/Linux 目标、自动更新、asar 内嵌 dsh。
- **验收口径（实施轮）**：三道门绿；`electron-builder --mac` 出 .app；**解锁后**真机启动（打包 app 与 dev 同为 Electron 渲染，锁屏建不出窗口，无头验收不覆盖打包产物）→ 写作区真模型对话链路（引擎经 RUN_AS_NODE 拉起、读 `userData` patch、连 127.0.0.1:8888）。
