## 一、背景与目标

织卷技能库（工作区 `skills/<名>/SKILL.md`，SKILL.md 格式 + renderSkillFile 生成出口 + 设置管理六函数 + matchSkillForInput 匹配）已有「**写/读/管**」三面，「内容从哪来」仍靠作者手写。主人 2026-09-17 即指明第四条路：**从作者的写作行为自动学习 → 沉淀为 skill 草稿**（人审后启用）。本期目标=把「自动学习」做成一期可用、零依赖、默认关、产出可审的完整闭环：

```
作者在织卷里写作（正文/批注/提案/修改卡） →
   周期触发（设置开关 + 打开项目检查“距上次≥N 天”） →
   本地纯统计采集行为信号（零模型零网络） →
   模板直出 skill 草稿（SKILL.md 格式，进草稿区） +
   人读报告（skill-creator 报告结构） →
   作者在设置页技能管理里审阅 → 转正启用
```

**为什么现在做**：① 前置三增量收口、技能库基建齐备；② 业界两直接先例（Grammarly Insights 周报=定时行为汇总产品形态；writing-style-skill ★270=「AI 初稿→作者改→diff→规则→更新技能」自动学习闭环）证明需求真实、形态可行；③ 织卷**数据源已天然齐备**（见 §4，history 自动快照=original/final 序列，零新埋点）。

## 二、真实调研（来源记档，2026-09-21 21:00 智能层轮，全部实抓实搜）

1. **Claude Code Skill Creator（官方技能**，github.com/anthropics/skills/skills/skill-creator/SKILL.md，raw.githubusercontent 直连实抓 33,168 字符，存档 /tmp/zj-learn/skill-creator.md）：
   - 创建循环=**Capture Intent**（从现有对话/范例提取工作流）→ Interview/Research → 写草稿 → 2-3 个真实测试 prompt → **with-skill vs baseline 对照运行（同轮并行、盲评）** → 按反馈重写 → 扩大测试集循环。
   - **关键判断：「Skills with subjective outputs (writing style, art) often don't need test cases」；「Subjective skills (writing style, design quality) are better evaluated qualitatively — don't force assertions onto things that need human judgment」**——写作风格类技能=主观输出，**定性评估、作者判断**，不硬上量化断言。→ 印证织卷「草稿人审后启用、不做自动应用」的决策。
   - 写作指引：向模型解释「为什么」而非堆 MUST；skill 要**通用**不窄化到具体示例；用 theory of mind。
   - 报告结构模板=**Executive summary / Key findings / Recommendations**（人读报告沿用）。
   - **Description Optimization**=生成 trigger eval queries → 人工评审 → 优化 description 循环（对应织卷 matchSkillForInput 的 description 质量→触发准确率）。
2. **Grammarly Insights 每周报告（定时行为汇总的产品形态先例**，support.grammarly.com 官方支持页实搜实读 2 篇：/hc/en-us/articles/115000090892（Weekly Insights 常见问答）+ /360003816132（周报如何生成））：
   - **定时周报形态**=email weekly report：Productivity（周总字数/与历史对比）/ Accuracy（纠错率）/ Vocabulary（唯一词数=词汇丰富度）/ Tone（语气分布）/ **最频繁错误**（产品文案原话=「designed to prevent you from making the same mistakes twice—or 17 times」→ 习惯性错误/偏好的重复检测=写作习惯的核心信号）。
   - 实现=写作时实时分析、统计绑定账户、持续更新——「周期性汇总作者行为数据」的成熟先例，正对主人「定时总结」诉求。
   - 另 2 页（同名系列）：**personal dictionary**（个人词典：词加入后不再被标错=个人 lexicon 正反馈）、**create style rules**（自定义规则：词/短语/格式三维，团队一致性；「how do I come up with new style rules」=brainstorm 常见问题→规则来源=观察/常见错误）。
3. **jzOcb/writing-style-skill（★270，GitHub api 实搜实抓 README 1,896 字符**，raw.githubusercontent 存档 /tmp/zj-learn/wss-readme.md）——**与本需求几乎同构的自动学习实现**：
   - 原理：`AI 用 SKILL.md 写初稿 → 你改到满意 → diff 两版 → 提取规则 → 更新 SKILL.md → 下次更准`；**只要两个数据点=original（初稿）与 final（终稿），中间改多少轮不管**。
   - 实现：`observe.py`（零依赖记录 original/final）+ `improve.py`（**LLM 分析 diff 提取规则；规则按置信度分 P0/P1/P2，P0 自动应用；每次更新前自动备份+一键回滚**）。
   - **与织卷的契合点（关键）**：织卷的 EditCard 修改卡=模型建议（before/after）、作者采纳=写入；history 自动快照=写盘前旧版（original）→ 写盘后新版（final）——**original/final 数据点已天然存在，无需新埋点**；P0/P1/P2 置信度分档=织卷「人审启用」也能参考（草稿内标注「证据强/弱」）。
4. **snowmays/style-alchemy（★41，上同**，README 11,725 字符存档 /tmp/zj-learn/alchemy-readme.md）——「样本→风格档案→skill」的批处理式先例：
   - 管道=归一化（统一 frontmatter/噪音剔除）→ 场景识别 → **通用 5 维**（标题术/开篇手法/段落节奏/语言风格=动词库·语气色板·口头禅·自创词典/结尾模式）→ **双产物=人读报告.md + 机器读 style_profile.yaml** → 可选一键生成 write-as-<id> skill。
   - **yaml 中间层定位**（原 README「为什么要 yaml」）：报告给人读、档案给机器读各司其职；人工可修、可融合、可评估（roadmap）——「风格=可编辑/可迁移/可校验的结构化资产」。
   - 与织卷差异：alchemy=一次性批处理（输入样本→出档案）；**织卷=周期自动（从行为流学习）+模板直出**（一期零模型）。
5. **织卷既有数据源（本轮代码级审计，全部真实存在、零新埋点）**——详见 §4 信号清单表。

**调研结论（创作/产品视角）**：
- ①「定时学习写作习惯」业界两条已验形态：**周期汇总报告**（Grammarly Insights 周报）与 **diff 规则学习**（writing-style-skill）。织卷=两者结合：周期触发 + 从「作者改动（diff）」学习——因为织卷的正文改动恰恰留下完整前后版本序列。
- ② 风格类学习的产物=**人读报告 + 机器可修订的结构化资产（skill 草稿）**，评估=作者定性判断（skill-creator 官方明示），**不自动应用**。
- ③ 信号维度有公认框架：用词（动词/口头禅/自创词典）、句法节奏（长短句/段落）、偏好模式（接受/拒绝什么、改什么）——织卷 wordfreq/历史/proposals 三者恰好各覆盖一面。

## 五、产出物与流程

```
触发（开关开 + 距上次≥7 天 + 打开项目/或设置页「立即分析」）
  → main/writingInsights.ts：
     gatherSignals(project) → { verDiffs[], adoptStats, annoIntents, wordStats }
     （全读本地：history 快照 + proposals json + 批注 csv + wordfreq 口径统计）
  → draftSkillFromStats(signals) → <工作区>/skills/_drafts/<YYYYMMDD>-写作习惯.md
     （front matter：name（英文 kebab，如 writing-habits）/description（中文≤500：做什么+何时用）/triggers（「写作习惯/我的风格」）/disabled:true（草稿默认禁用！）——转正时作者改）
     + 正文：【我的写作习惯】Evidence 强度标注（强=≥N 次观察/中/弱）+ 规则条目（通用化表述，不写死具体句例）+「为什么」一句话（对 agent 解释）
  → reportFromSignals(signals) → <工作区>/skills/_drafts/<YYYYMMDD>-写作习惯-报告.md
     （Executive summary / Key findings（数据带出处：章号/次数）/ Recommendations（建议作者考虑转正或调整哪条））
  → 写 .zhijuan/insights-state.json { lastRunAt, lastDraft }
```

**转正路径**（数据链，与设置管理复用）：作者在设置页技能管理（体验层 UI）看到 `_drafts/` 草稿 → 「转正」= 校验（validateSkillDraft 语义：name=目录名、description 非空）→ 移到 `skills/<名>/SKILL.md`（重名=先备份旧的）→ 参与注入/匹配。**一期数据链实现转正 IPC；UI 归体验层。**

## 九、不做（边界）

- 不自动启用/替换任何技能（草稿默认 disabled:true、需转正）；
- 不做系统级 cron/后台常驻（App 打开时检查，同批注先例）；
- 不采 save-trace/write-log（时序信号与风格无关）；
- 不引分词器/embedding（词表式+字符统计，零依赖红线）；
- 不动 wordfreq/proposals/history/批注既有语义。
