
# 织卷 V2 · 模块设计（2026-09 定稿方向）

> 权威关系：本文件是**模块级**权威源，受 docs/架构设计-V2.md 约束（那里是架构级）；两者相冲突时以架构文档为准，且须回改这里保持一致。
> 已拍板：V1 遗产整体搁置（D-V2-1）；一章一个时间切片（D-V2-2）；设定改动走提案制、正文走“应用到章节”显式动作（D-V2-3）；采集走后端管道（D-V2-4）；验收改为“写完一个中篇且各切片设定与正文自洽”（D-V2-5）。

## 一、目标与范围

把织卷重塑为**通用的多项目 AI 辅助创作工作台**：

1. **多项目**：首页是项目管理，每个项目一部作品，完全独立。
2. **第一期纯文档**：正文、人物、世界观、素材库全是 markdown 文件，无结构化设定库。唯一约定是章节头的切片 front matter。
3. **时间切片联动**：正文每章 = 一个时间切片；保存正文 → 生成“切片同步提案” → 主人确认 → 更新人物/世界观/环境文档。
4. **右侧 agent**：正文创作以“markdown 编辑 + 右侧对话”为主通道，可选中段落引用，相关设定都在 agent 手里。
5. **素材库 + 联网采集**：按类别文档管理，支持表单发起采集 → 本机管道回填。

第一期明确**不做**：结构化设定库、曲线/导演板/分幕/兑现、多用户、云同步、付费格式支持。

## 二、全局架构

### 2.1 进程模型（沿用现有 Electron）

- **主进程（main）**：所有文件读写、LLM 调用、采集管道对接的 IPC。文件操作统一走主进程派生的 `fileStore`，渲染层不直接碰磁盘。
- **预加载（preload）**：把 API 以 `window.zhijuan.*` 暴露（沿用现有桥，按需扩展）。
- **渲染（renderer）**：React + Tailwind + shadcn/ui；页面组件只消费 `zhijuan.*` API 和本地状态。

### 2.2 存储形态

所有数据在 `库根/<项目ID>/` 一个目录里，纯文件、明文、可入 git：

```
<项目ID>/
  project.md                  # 项目封面：简介、时间线总纲、切片清单、约定说明、目录地图
  正文/
    第NN章_<题名>.md          # 每章一个文件，头部带约定头（见 4.2）
  人物/
    总览.md                   # 角色目录 + 各角色在哪切片出场
    <角色名>.md               # 角色档案；含每切片的状态小节（由提案制维护）
  世界观/
    总纲.md                   # 长期不变的世界设定
    切片_<切片名>.md          # 每切片当刻的世界状态（按需创建）
  素材库/
    索引.md                   # 类别目录 + 采集入口说明
    <类别>/
      <素材>.md               # 每个素材一个文档
    采集池/
      任务_<时间戳>.md        # 采集任务卡（带状态 front matter）
  .zhijuan/                   # 工具数据（允许结构化；不算“设定”）：
    proposals/*.json          # 提案（待确认/已接受/已拒绝）
    sessions/*.jsonl          # agent 会话记录（按项目一份）
    tasks/*.json              # 采集任务元数据（状态机）
```

### 2.3 约定头（front matter，全文唯一“半结构化”约定）

每章正文章首：

```yaml
---
章号: 3
题名: 夏夜的信
切片: 第二幕_台风夜     # 即故事时间切片名；一章一个切片（D-V2-2）
时间: 2026 年 8 月某夜   # 人读的故事时间描述
涉及人物: [林晚, 顾知远]
---
```

- 解析为一个很小的 util（只取章号/切片/涉及人物），不引入 yaml 库也行（正则足够）。
- 约定头之外一切自由书写。

### 2.4 文件变化可见性

主进程用 **fs.watch**（或 chokidar）监听当前打开项目的目录树，把变化广播到渲染层 → 界面实时反映外部写入（比如采集管道回填、git 回滚）。

## 三、页面地图与导航

```
首页(/)                    → 项目卡片网格；新建/打开/删除/导入
  └─ 项目工作区(/project/:id)
       ├─ 侧边栏（常驻）：返回首页 | 项目名 | 四大板块 | 设置
       │    ├─ 正文创作    /project/:id/novel
       │    ├─ 人物设定    /project/:id/characters
       │    ├─ 世界观设定  /project/:id/worldview
       │    └─ 素材库      /project/:id/library
       ├─ 顶部：全局命令（Cmd+P 快速跳转）、保存状态、回首页
       └─ 设置页（模式窗口或独立路由）
```

键盘优先：`Cmd+S` 保存正文、`Cmd+P` 全局搜索文件、`Cmd+K` 唤起项目内命令面板。

## 四、模块 A：项目管理（首页）

**目的**：多项目入口，是“工作台”形态的起点。

### 布局

- 顶部：应用名 + 「＋ 新建项目」主按钮 + 库根路径（可改）。
- 主体：项目卡片网格（封面渐变块用 stable seed 生成，避免每次不同）。每卡：**名称 / 简介 / 章节数·人物数·素材数 / 更新时间 / 最近章节**。
- 底栏：当前库根、右键菜单（打开目录 / 导出 / 删除）。

### 交互

1. **新建项目**：向导两字段（名称、简介）→ 主进程创建目录骨架并写入 project.md（含时间线总纲空模板、素材库索引模板）→ 进入工作区。
2. **打开项目**：卡片点击进入；也可“导入已有目录”（给一个目录，补全缺失的骨架目录并生成 project.md，不覆盖已有内容）。
3. **删除**：移到废纸篓（主进程 shell.trashItem），不硬删。

### 数据

项目列表 = 扫描库根下含有 project.md 的目录；每个项目读 project.md 的 front matter（名称/简介/时间线）还要统计正文、人物、素材库文件数。库根路径存设置。

### 边界

- 目录里文件很多时不阻塞：扫描用异步 + 节流。
- 无库根时引导创建。

## 五、模块 B：项目工作区外壳

**目的**：四大板块的统一容器，承载项目级上下文。

- **侧边栏**：项目名（点击回 project.md）→ 四大板块导航（带各板块当前计数徽标）→ 底部：采集入口快捷方式、设置入口。
- **顶栏**：当前板块名、文件名；右侧：**保存状态灯**（已保存 / 有未保存改动 / 同步中）、**「待确认提案 N」徽标**（点击即打开提案抽屉，见模块 G）。
- 布局用三列：侧边栏（固定 220-260px）｜内容区（主轴）｜agent 区（仅正文创作页有，见模块 C，默认 360px 可拖宽）。

## 六、模块 C：正文创作（核心）

### 6.1 页面布局（三列）

```
┌──────────┬───────────────────────┬───────────────┐
│ 章节列表  │  markdown 编辑器        │  agent 区      │
│ (左,240px)│  (中,弹性)             │ (右,320~480px) │
└──────────┴───────────────────────┴───────────────┘
```

### 6.2 章节列表（左列）

- 按章顺排；每项：章号 + 题名 + 切片名 + 字数 + 状态点（已有正文 / 只有约定头 / 有未确认提案）。
- 「＋ 新章节」：创建时填**新章向导**（章号自动 +1、题名、**切片名**、涉及人物、一句话梗概）→ 生成带约定头的空正文文件。
- 右键章节：重命名（改题名与文件名）、删除、导出单章 md。

### 6.3 编辑器（中列）

- Milkdown WYSIWYG（ProseMirror 内核）。
- 左侧留白足够宽（纸面感），最大行宽 ~680px 居中，正文区 16px 行高 1.75；约定头可编辑也可只读展示。
- 字数统计：章字数；底部状态栏显示“上次保存时间”。
- **选中即引用**：选中一段 → 悬浮工具条出「交给 agent →」→ 该段作为**引用块**进入右侧对话（带来源标记：章号 + 首尾词），对话里高亮显示是哪一段。
- 保存：`Cmd+S` 或失焦自动（防抖 2s）；保存 = 写文件 + 触发切片同步（见 6.5）。

### 6.4 Agent 区（右列）

- **会话**：按项目一个长期会话（`.zhijuan/sessions/<project>.jsonl`），跨章保留；可清空/改名。顶部显示当前上下文状态。
- **上下文装配（v1 朴素版）**：当用户停在某章时，发给模型的系统侧写自动带上：
  - 当前章正文（未选段时），或选中段（已选中时）；
  - 该章**切片名**对应的设定：涉及人物的档案 + 其在该切片的状态、“世界观/切片_当前.md”全文、环境相关条目；
  - 素材库索引（做成小标题清单，按需展开）；
  - 上一章结尾 ~800 字（承接）。
- **生成**：调本地 LLM（设置里的端点），流式输出（SSE）。回复用 react-markdown 渲染。
- **落盘动作**：回复里的代码块或整段带两个按钮——**「插入到光标处」** 与 **「替换选中段」**（若当前有选中）；点击即应用（正文是创作本体，这里是**显式应用**，不走提案，符合 D-V2-3）。
- **agent 可做之事（v1）**：续写本章 / 改写选中段 / 列本章大纲拟稿 / 对当前切片设定提问 / **建议素材采集**（生成任务卡草稿）/ **提出设定变更**（生成提案，见模块 G）。
- **“相关设定都在 agent 下”**：agent 区能直接看到当前切片用到的人物、世界观、素材条目；“提到谁但档案里没有”时提示主人可新建角色。
- 长度预算：上下文脚本按“当前章正文 + 相关档案 + 切片设定 + 素材索引”拼装，正文超长时只带本章 + 上一章尾部，完整前文通过这些设定文档代理。

### 6.5 保存 → 时间切片同步（核心联动）

保存正文时主进程触发一次**切片同步工作流**：

1. 读本章约定头 → 得 切片名 + 涉及人物。
2. 组装配送：本章正文全文 + 前一章切片的状态基准（上一切片的人物状态小节、世界观切片文件，若无则用总纲）。
3. 调 LLM，产出一份**拟切片同步提案**（结构化 JSON，这是工具数据不是设定）：
   - 每个涉及人物：本切片内发生了什么 → 状态如何变化（只列出变化点）；
   - 世界观：本切片揭示了什么规则 / 发生了什么事件；
   - 环境：本章出现的新地点、器物；
   - 每项带：目标文件、目标锚点（如 “人物林晚.md” 的 `## 切片：第一幕_x`）、拟写内容。
4. 提案落入 `.zhijuan/proposals/`，界面顶栏“待确认 N”亮起。
5. 主人逐条确认（见模块 G）→ 接受项写入对应文档锚点处（无此小节则创建）；写入时保留“以正文为准”的基调，不改正文。

> 约定：**切片同步只做“新增/修正设定”，不改正文**；“正文为准”永远成立。若正文本身就是从设定反写的（先定切片再写正文），同步结果自然为空或极少。

### 6.6 边界与异常

- LLM 不可用时：保存只落盘正文，同步失败在 agent 区提示，决不影响“写”本身（写优先）。
- 提案过时（正文又改了）：写入前展示“可能已过时”提示，仍可强制写入。
- 章文件被外部改：以 watcher 收到的最新为准，冲突时提示。

## 七、模块 D：人物设定

**目的**：每角色一个文档，静态档案 + 按切片的状态小节。

### 布局与交互

- 左列：总览.md + 角色列表（按总览里登记）；顶部「＋ 新角色」（填名字、一句话定位 → 生成档案模板）。
- 右列：选定角色的 markdown 编辑器（同 Milkdown）。
- 顶部工具栏：**「按当前切片查看」** —— 当在正文创作里切到某章时，这里可跳回“该章切片下的人物状态”；本质是把光标定位到对应角色文件里的 `## 切片：<当前>` 小节。
- 变化来源：**只由提案制写入**（保存正文的同步提案、或 agent 在对话里提出的设定变更提案）；主人也可全手动直接编辑文档（两者并存，手动优先）。

### 文件模板（角色档案）

```markdown
# 林晚
> 一句话定位：……
## 基础设定（不变项）
（姓名、年龄、身份、外貌、性格、背景）
## 切片：第一幕_夏夜
（本切片状态：在场、关系、身体与心理状态、知晓的信息）
## 切片：第二幕_台风夜
…
```

### 边界

- 一个角色有几十个切片小节后文件变大 → 出现频率低的小节可折叠（界面侧），文件本身保持顺序不变。
- 角色重命名：提供“重命名”动作（改文件名 + 全局替换引用），第一期可先只改文件名并在总览里标注。

## 八、模块 E：世界观设定

- 结构同人物：左列文件列表（总纲 + 切片文件），右列编辑器。
- 总纲 = 长期不变项；每个切片一个“切片_<切片名>.md”存当刻世界状态。
- 写入来源：提案制（保存正文同步）+ 手动编辑。
- 与人物差别：无“按角色过滤”，只有“当前切片定位”。

## 九、模块 F：素材库

### 布局

- 左列：类别树（自由建）＋「＋ 新类别」；「采集池」固定入口。
- 右列：所选类别下的素材卡列表（预览首屏 + 标签 + 更新时间）→ 点开即文档编辑；每个素材一个 md。
- 顶部：搜索（文件名+全文）、「＋ 新建素材」、「**＋ 发起采集**」。

### 采集流程（见模块 H 主体）

**发起采集**表单：需求描述（必填）/ 关键词 / 期望来源（如图站、某站）/ 归属类别 → 生成任务卡（`素材库/采集池/任务_<ts>.md`，带 front matter：status:pending）＋ 匹配的 `task` 元数据 → 本机采集管道处理 → 回填。

### 素材文档模板

```markdown
---
tags: [类别, 用途标签]
来源: url / 书名 / 自研
创建: 2026-09-02
---
# 素材名
（正文）
## 可复用点
（怎么用进故事）
```

### 边界

- 素材可被正文引用（全文关键词检索即可，本期不做引用关系图）。
- 采集回填的是“整理后草稿”，**算新增素材**，需主人过目（可编辑可删），不自动进正式类别。

## 十、模块 G：提案系统

**目的**：把“agent 想改设定”的每个动作变成可审计、可确认的条目。

### 数据结构（`.zhijuan/proposals/<id>.json`）

```jsonc
{
  "id": "p_2f31",
  "source": "slice-sync | agent-chat",   // 来源
  "chapter": "第03章",
  "slice": "第二幕_台风夜",
  "status": "pending | accepted | rejected | stale",
  "createdAt": 0,
  "items": [
    {
      "target": "人物/林晚.md",
      "anchor": "## 切片：第二幕_台风夜",
      "kind": "upsert-section | append",    // 本期就这两种
      "before": "（原文锚点附近内容，前若干行）",
      "after": "（拟写入的内容）",
      "reason": "本章正文中她与顾知远破冰，状态需更新"
    }
  ]
}
```

### 交互

- 入口：顶栏“待确认 N”徽标（点击展开右侧抽屉）；agent 区里 agent 提的设定变更也汇到这里。
- 每条提案卡片：来源、关联章、目标文件；逐条展开 **before → after 对照**；按钮 **接受 / 拒绝**；可“全部接受”。
- 接受 → 主进程写入目标文件对应锚点（先找锚点，找不到则在末尾创建小节并加注释）；拒绝 → 状态置 rejected。
- 全部提案可回看（已处理列表），本期不做撤销（文件本身可 git 回滚）。

### 边界

- 写入前用 before 做锚点匹配校验，若原文已变（被手动编辑），标记 stale 并在 UI 提示“原文已变，请人工确认”。
- 提案带字数上限（每条拟写 ≤400 字），超长拆多条。

## 十一、模块 H：联网采集管道（本机）

**目的**：素材库“按需求联网采集”，且 App 自身零网络依赖。

> 任务卡**实际落盘样例**（测试 · 素材库验收 项目可见）：`素材库/采集池/任务_*.md` 顶部 front matter 依次为
> `status: pending` / `类别:` / `关键词: [a, b]` / `需求: …` / `来源:` / `创建: …`；好文案见项目内文件。

### 通道（约定目录）

1. **App 侧**：发起采集 → 完**整**落在 `素材库/采集池/任务_<ts>.md`（front matter：status: pending / 需求 / 关键词 / 期望来源 / 归属类别）+ `.zhijuan/tasks/<id>.json`。
2. **管道侧（Hermes / 本机）**：一个常驻或定时脚本扫描“库根 */素材库/采集池/”下的 pending 任务：
   - 用现成 web 栈执行：web_search（本地 searxng）→ web_extract → 需要时走专用浏览器 / FlareSolverr；
   - 按“需求 + 关键词 + 用途”把抓取结果**整理成素材草稿**（模板见模块 F）→ 写入 `素材库/<归属类别>/`；
   - 回填任务卡：front matter 改 status:done，附结果文件路径 + 摘要；失败则 status:failed + 原因。
3. **App 侧**：采集池列表通过文件 watcher 实时刷新；任务卡点击可见结果；草稿素材在正式类别里出现（可继续编辑）。

### 触发方式（一期可都支持）

- 定时扫描（如每 30 分钟），顺手还能做批注 cron 那种静默；
- 或主人直接对 Hermes 说“把素材库采集池跑一遍”，即手动触发。

### 边界

- 抓取源可能失败（墙、风控）：复用既有经验（searxng 直连 + FlareSolverr），失败要写明原因可重试。
- 采集是**后台低优先**任务，不阻塞正文写作；任何时刻写优先于采。

## 十三、UI 设计系统（技术选型落地）

### 13.1 技术栈

| 用途 | 选择 | 理由 |
|---|---|---|
| 样式 | Tailwind CSS v4 | 原生支持 design tokens，v4 零配置好上 |
| 组件库 | shadcn/ui（Radix 基座） | 当前最具设计美感、可深度定制的 React 组件层；砌件即产出，符合“剪裁而非套壳” |
| 编辑器 | Milkdown（ProseMirror 内核） | WYSIWYG markdown；支持自定义 keymap 与命令 → “选中即交给 agent”可落地 |
| agent 回复渲染 | react-markdown + remark-gfm | 轻量、够用 |
| 图标 | lucide-react | 与 shadcn 配套 |
| 状态 | zustand | 轻量，配合选择器避免全树重渲 |
| 文件监听 | 主进程 chokidar 或 fs.watch | 界面跟外部变化（管道回填等） |

### 13.2 设计语言（暖纸面 ＋ 精密中性铬）

**基调**：浅色、暖、慢下来的写作台；用 Linear 的克制喷绘应用框架，用 Notion 的暖纸面做画布。两套模板的 tokens 已在模板里，只取其精神，不照搬品牌色。

**设计原则**：
1. 中性偏暖的浅色背景（纸面）；发丝边框（`1px solid color-mix(in srgb, currentColor 10%, transparent)`）；阴影几乎不用，用边框和背景层次表达层级。
2. 全体 UI 只用**一个强调色**（青黛 teal-600 `#0f766e` 系），只用于：主按钮、激活态、链接。状态色（成功绿/警示橙）限定小剂量。
3. 字体：UI 用系统中文栈（PingFang SC）；**正文画布用衬线**（Noto Serif SC，中文小说正文的纸面质感）；正文区 16px / 行高 1.75；代码与元信息用等宽（JetBrains Mono）。
4. 每屏一个焦点动作；工具栏哑光低调（图标为主，字为次）。
5. 键盘优先：Cmd+S 保存、Cmd+P 开文件、Cmd+K 面板、选中段即可用快捷键交给 agent。

**主题**：默认“暖纸”；可选“深色”（Linear 的深色层级思路：近黑背景 + 半透明白细边框 + 同强调色），两套都从同一组 CSS 变量切入（`--bg`, `--surface`, `--border`, `--text`, `--accent`…）。

### 13.3 组件清单（shadcn 基础件 + 自研件）

- 基础：Button、Input、Dialog、DropdownMenu、Popover、Tabs、ScrollArea、Separator、Badge、Tooltip、ContextMenu、Command（Cmd+K 用）、Resizable（侧边栏拖宽）、Toaster。
- 自研：`SectionNav`（侧边栏）、`ChapterList`（章节列表）、`ProposalCard`（提案卡）、`TaskCard`（采集任务）、`AgentPane`（对话区）、`PaperEditor`（Milkdown 封装，含约定头展示）、`PendingBadge`。

## 十六、风险与取舍

- **无结构化**：跨切片检索靠全文搜索，长项目可能吃力 → 若以后需要，再在 `.zhijuan/` 里加索引，设定本体依然是文档。
- **代理靠设定文档代替前情全量**：切片设定写得勤，agent 记忆就好；所以把“保存即生成同步提案”做成默认静默工作流。
- **提案可能过时/只见树木**：用 before 锚点校验 + 过期标记，保证不算错账。
- **采集结果质量**：管道只出“草稿”，正式入库靠主人过目，不冒充成品。
- **覆盖范围控制**：第一期的边界（第一节）就是“不做清单”，任何想加的都先回本文审阅。
