# 织卷 · 长期计划（ROADMAP）

> 本文档是织卷的规划权威源。每次迭代前先读它；每个里程碑完成后更新它。
> 定位由主人 kk 定稿（2026-08）：织卷不是通用写作工具箱，而是围绕两条**引擎**做深做透的 AI 辅助创作工作台。

## 一、定位（主人钦定的两个核心）

1. **要素引擎** —— 关键要素的设定与召回，解决长文章后期「啃书」问题（写 50 章以后不失忆、设定自洽）。
2. **导演引擎** —— 用情绪曲线 + 人物曲线作为每一章的导演指令综合控制生成，让 AI 生成的故事**不再平淡**。

其余功能都是这两条主线的配套，砍多余、不铺摊子。

## 一点五、V2 架构转向（主人 2026-09 定稿）

> 主人重新定稿了织卷的架构方向，完整设计见 **docs/架构设计-V2.md**（新架构权威源）。要点：
> 1. **泛化**：不参考任何进行中具体项目，通用创作工作台。
> 2. 核心：**素材库积累** + **面向时间切片**的人物/世界观/环境设定；切片承载每章当下的世界状态。
> 3. **第一期全部文档化**（markdown），不做结构化存储；唯一约定是章节头的切片 front matter。
> 4. 首页＝项目管理；项目内左侧边栏：正文创作 / 人物设定 / 世界观设定 / 素材库。
> 5. 正文创作＝markdown 编辑器 + 右侧 agent 区，边聊边生成；可选中段落引用；相关设定都在 agent 下；**保存正文 → 触发更新当前章节对应时间切片的其他设定**。
> 6. 素材库支持按需求联网采集（素材库页表单 → 采集池 → 本机采集管道回填）。

## 二、现状快照（v0.1，2026-08，V1 历史）

### 已有（保留）
- 项目库：`~/Documents/织卷项目库/<id>/project.json`，纯 JSON、本地方便入 git
- 数据模型：Worldview / Character（自由字段）/ Chapter（elements、premise、curves、beats、content）/ SeriesCurve / PlotBeat
- 曲线采样：把曲线 0~100 分 8 段算出趋势（骤升/缓升/平缓/猛跌）+ 情节点定位，结构化进 prompt
- 生成：拼整包 prompt → 本地 vLLM（127.0.0.1:8888，deepseek-v4-flash-0731，1M 上下文）；`content || reasoning` 双保险已在
- 章节导出 md

### 短板（对应两个痛点）
1. 上下文是**整包硬塞**：全部世界观 + 全部人物全量进 prompt；长文时设定膨胀 → 噪音盖过信号；正文本身从不进 prompt → 前情全忘。
2. 曲线只是**参考建议**：一次性生成整章，长度一上去曲线契约就在中间流失；人物曲线只是抽象状态，没映射到「该角色具体怎么动」；写完没有「曲线承诺是否兑现」的检查。

## 三、路线图（按里程碑推进）

### M1 要素引擎（先做 —— 导演引擎的输入也要靠它保证最新状态）

**M1.1 设定条目化（数据模型改造）**
- 把世界观规则、人物身世/档案等大文本升格为**条目卡片** `Element`：id、分类（世界观/人物/场景/道具/规则）、标签、正文、状态、版本、更新时间。
- 各章的 `elements`（本章要素）可引用条目 id 或标签组，单独标「本章强制」。
- 平滑迁移：旧 project 加载时把自由文本折成条目，已有项目无缝可用。

**M1.2 前情记忆（每章写完后）**
- 每章完成后自动产出一份「章节审计」：一段事件摘要 + 出场人物各自的**结束状态快照** + 已兑现的伏笔 + 新埋的伏笔，结构化落库。
- 伏笔台账：跨章节前后指针；生成时把「未兑现伏笔清单」放进 prompt，从根上杜绝烂尾。

**M1.3 按需召回（每次生成前）**
- **组配器**：由本章要素（谁 / 在哪 / 要什么）+ 曲线情节点，算出召回清单：
  - 出场人物的完整档案 + 最近几章状态轨迹；
  - 本章相关的设定条目（场景、规则、器物）；
  - 前 1~2 章摘要 + 更早的衰减摘要。
- 第一版用纯本地标签/关键词匹配（零新依赖）；后续数据量上来再加 embedding 增强（可选）。
- **预算硬控**：设定 ≤2000 字、前情 ≤1200 字，超出按优先级截断 —— 长文就在这里保持不糊。

**M1.4 设置页**
- LLM 端点 / 模型从写死处（ChaptersView.doGenerate）抽到设置，README「已知限制」就此了结。

### M2 导演引擎（让曲线有牙齿）

**M2.1 曲线硬约束（导演板） ✅ 完成（2026-08-13）**
- `shared/director.ts`：把曲线切成 8 段，每段给出**戏剧任务**（白热化 / 推进 / 拉锯 / 低谷），定位**本章波峰（climax）与波谷（nadir）**，做**落差检测**（相邻段骤变时强制「必须用具体事件撑起」），情节点按进度归入对应段。
- generator 的曲线段由「采样参考」升级为「导演板硬指令」直达 prompt；verify-director 6/6；全 verify 现为 47 断言。

**M2.2 分幕生成 ✅ 完成（2026-08-13，提交 045ecb3）**
- `shared/acts.ts`：把导演板 8 段按戏份权重均衡地切成 **3~6 幕**（波峰段只属于一幕、落差段所在幕强制事件承载），确定性的线性切分；每幕带自己的**主调（白热/推进/低谷/拉锯）与戏剧任务**，`renderActDirective` 只下发本幕的段作为硬指令。
- **逐幕生成**：generator 按幕单独请求，每幕 prompt 带「前一幕末状态」（尾段约 1000 字）承接续写，结尾定格留给下一幕，曲线契约整章贯彻；支持 **「回滚到某幕重生成」**（保留前 N 幕，从第 N+1 幕起重写）。
- 数据：`Chapter.acts?: string[]`（新增可选字段，旧章节 normalize 自动回填为整幕，不破坏兼容）。
- verify-acts 16 断言（含回滚重演通路的 e2e）；全 verify 现为 **63** 断言；typecheck / build 全绿。

**M2.3 人物曲线 → 行为轴 ✅ 完成（2026-08-13；按主人要求升级为可视化可拖拽曲线）**
- `shared/axes.ts`：`CurveAxis`（自由命名）+ 通用三档（被动·生涩 / 拉锯·试探 / 主导·放开）+ 可选的预设档位（主动权/压迫感/距离/情欲/羞耻防线 的库保留为可选）；`pivotAxes` 把旧单轴曲线合成为一根轴（向后兼容）；`bandAt` 按值取档给动作要求；`translateAxisCurve` 把一根轴曲线按段采样成段级**动作硬命令**，档位跨段跳变时强制「必须用具体事件接住这一跃」。
