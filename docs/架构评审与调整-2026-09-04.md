## 二、分组合理性判断

1. **store.ts（369 行、17 个 export）是上帝文件**：职责包括 settings（normalize/get/set）、路径解析（workspaceDir/libraryRoot/abs）、项目（create/list/remove/import）、文档（read/write/list）、watcher、工作区文档。根因是 S1~S5 螺旋生长时图快归拢。**要拆**——最少的一刀是 **settings 独立成 `main/settings.ts`**（settings + workspaceDir + libraryRoot 归它），store 只留「项目 + 文件 + watcher」。拆分后每扩展一个厂商字段、路径规则都不碰 store。
2. **agent 检查器在复制样板**：audit / outline / triage 每个都重复「驱动会话 → 注入上下文 → 跑模型 → 结构化解析 → 事件返回」这五层（已有 references/agent-subtask-recipe.md 作证）。加第四个检查器就要再抄一遍。**要抽象一个 `agent/subtask.ts` 骨架**（runSubtask(任务定义)），现有三件套是它的第一批消费方——这是**最强扩展点**，未来任何新助手都走同一骨架。
