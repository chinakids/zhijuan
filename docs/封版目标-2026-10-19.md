# 织卷 · 封版目标与判定（2026-10-19 主人拍板）

> 本文档是织卷**封版阶段**的权威源，优先于 ROADMAP 的一般性增量条目。
> 定位：织卷已过「功能堆砌期」，进入「达成封版验收」阶段。以下两项目标**都达成**才可宣布封版。

## 一、封版目标（主人 2026-10-19 拍板）

### 目标 1：完成 D-V2-5 中篇验收（核心）
- **口径**：用织卷**完整写一个**含**至少两条时间线交错叙事**的中篇。
- **验收标准**：该中篇各**时间切片**设定、**人物**状态、**世界观**状态与**正文自洽**；两线各自切片设定与正文自洽、人物状态分线不串线；时间线视图可按线查看。对应 D-V2-5（2026-09-16 修订版，纳入多时间线口经）与 D-V2-14。
- 这是织卷**一直没做**的终极闭环验证——功能很多，但「用它真的写完一个中篇小说并自洽」尚未验证。

### 目标 2：发布正式 1.0
- **口径**：织卷达到**稳定**（不崩、核心链路稳；三道门 + 单测 + 关键冒烟全绿）。
- **发布**：产出正式 mac 版（稳定包）；仓库**公开**且 **GitHub Actions 可用**（CI 自动跑 typecheck/单测/build）。
- 注：此前 Actions 因 GitHub 账号 billing 锁定无法运行——**发布 1.0 前必须解决** billing 问题让 Actions 能跑。

## 二、封版后约定
- 达成以上两目标即**封版**：冻结新增功能，转入维护期（只修 bug / 保测试 / 保打包）。
- 封版前不再新增「好玩但非必要」的功能；所有推进器轮次向封版目标聚焦，砍掉与双目标无关的摊子。

## 三、推进器方向调整（自本文档起生效）
- 四个模块推进器从「自由加功能」转向**围绕封版验收**：优先补齐「用织卷写完中篇并自洽」所缺的能力 / 卡点，以及「稳定 + 可发布」所缺的工程项。
- 无任务≠停（主人长期项目原则），但能力发现优先选「为达成封版验收服务」的事项，不做与封版无关的新玩具。

## 四、现状（2026-10-19）
- V2 主体 S1-S8 已全部落地；大量深化迭代（skill 能力/写作习惯学习/批注/@引用/命令槽位/工具链/错误态/健康栏/窄窗/多时间线等）已收口。
- 三道门 + ~1260 单测 + 多支无头冒烟全绿；已有 mac dmg 打包底本。
- **尚未做**：① 真实「写完含双时间线交错的中篇并自洽」的端到端验证；② 正式 1.0 发布与 Actions 打通。

## 五、与既有文档的关系
- D-V2-5 / D-V2-14：V2 一期验收口径（本文档目标 1 沿用）。
- 周交付窗口机制（docs/周交付窗口-机制-2026-09-16.md）：封版前的增量仍走周交付，但增量选择向封版目标收敛。
- ROADMAP：本文档是封版阶段权威源；ROADMAP 的一般性增量条目在封版前不再驱动新功能。
