## 2026-09-09（本轮提交：a990682，fix(acts)）分幕缺段防护——不再静默产出「有洞草稿」

**起点**：健康检查（工作树干净、三道门全绿 112 例）后，按「每轮审视架构找问题」扫近期代码，发现 M6 分幕生成链路一处真实缺陷：某段写成太短/空（重试后仍 <120 字）时，`runActs` 原逻辑只是 `if (t)` 不满足就不 push、**继续跑下一段**，最终把缺了整段内容的草稿照常写盘并报 `ok:true`——界面还显示「✓ 已按导演板分 N 段起草」。草稿头没有任何缺段提示，用户直接两击「采纳为正文」就是**带着空洞的残缺章节**。这违背「先设定后成文」成品必须是完整正文的预期，属于静默失败。

**做了什么**：
- `src/main/agent/acts.ts`：写段循环改为长度 >= MIN_ACT（120 字，与 retry.check 同一质量口径）才收入草稿并更新承接链；否则记入 `failed[]`。全部段失败 → `ok:false` 并报「第 1、2、3 段失败」；部分失败 → 结果附 `failed[]`，草稿头部注入 `failedNote`（⚠️ 第 X 段未按导演板写成，草稿只含 n/N 段…请勿直接采纳）；`buildActsDoc` 增可选 warn 参数。承接链语义不变：缺段处后续段仍从上一个成功段末文续写，草稿拼起来仍是连续文本，只是少了那段的戏。
- `src/preload/index.ts`：agentActs 返回类型补 `failed?: number[]`。
- `src/renderer/src/pages/Outline.tsx`：分幕完成消息区分「完整」/「缺段」——缺段时明示「第 X 段没写成，草稿只有 N 段（缺段处会断戏）：请重新分幕生成或手动补」。
- `tests/unit/acts.test.ts`：+4 例（buildActsDoc 注记有无、failedNote 文案、部分失败全流程、全部失败报段号且不落盘）。

**验证结果**：`npm run typecheck` ✅ / `npm run build` ✅ / `npm test` **116 例全过**（112+4）✅；提交 a990682。
