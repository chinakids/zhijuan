## 2026-09-09（本轮提交：a990682，fix(acts)）分幕缺段防护——不再静默产出「有洞草稿」

**做了什么**：

- `src/preload/index.ts`：agentActs 返回类型补 `failed?: number[]`。
- `src/renderer/src/pages/Outline.tsx`：分幕完成消息区分「完整」/「缺段」——缺段时明示「第 X 段没写成，草稿只有 N 段（缺段处会断戏）：请重新分幕生成或手动补」。

**起点**：健康检查（工作树干净、三道门全绿 116 例）后按上一轮「下一步 1」候选开工：分幕某段失败时（a990682 已防护：不静默塞残段、草稿带警示），用户只能「重新分幕生成」（每段约一轮完整请求、全量重跑白扔已写成的段，还可能在别的段上再失败）或手动补。本轮做「补写缺段」：只重写失败段，已写成的段原样保留。

**设计取舍（拍板并落档）**：
1. **草稿格式升级为带段标记**：每段以「## 第 N 段」标题开头（新 shared/actsSeg.ts，纯逻辑可单测）。理由：草稿本来就是给人审读的产物，段边界可见（哪段缺了一目了然）；程序可按标题切回各段原文，补写/重写才有定位依据；采纳为正文时（shared/actsAdopt.extractActsBody）剥掉标记与「> ⚠️」警示行（此前进度的失败草稿采纳会带警示行进正文，顺带修掉），正文不带分幕痕迹。**不引入结构化存储**（仍是 markdown 约定，符合一期「全部文档化」）。旧格式无标记草稿读不出分段 → 补写报「旧格式，请重新分幕生成」，不静默乱补。
2. **接口**：runActs 增 `opts?: { only?: number[]; onlyFailed?: boolean }`（第五参，冒烟旧调用不破）；`onlyFailed` 由主进程读草稿警示（parseActsWarn 从「⚠️ 第 1、3 段未按导演板写成」抽段号）自动定位缺段，UI 只传一个开关。承接语义与全量一致：补写段的 prevTail = 编号更小的最近已存在段末文；补写首段用上一章结尾。补写成功后**后续已存在段不动**（它们原本就是跳过失败段写的，语义本来如此，文档注记）。
