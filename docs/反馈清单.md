# 织卷 · 反馈清单（用户反馈收集与落实台账）

> 本文件是**用户反馈的权威台账**。来源：飞书「织卷反馈群」（主人 kk 在此群反馈织卷问题）。
> 闭环流程：**收集**（群内反馈落档本文）→ **分类**（模块归属＋严重度）→ **落实**（小改当场修；大改排期给对应模块推进器）→ **验证**（三道门＋冒烟/真机）→ **回群汇报**（说清改了什么、怎么验证的）。
> 规则：**每轮模块推进器开工必须先查本清单**——归属本模块且状态为「待落实／落实中」的条目必须排进本轮（或在当轮档案写明不做的理由）；解决后回写状态与提交号。主人反馈闭环，漏一条都不行（文字>大脑，落档为准）。

## 一、状态流

| 状态 | 含义 | 负责人 |
|---|---|---|
| 待分类 | 刚收到，未拆解 | 主会话（收集当天完成） |
| 待落实 | 已分类（模块＋严重度＋方案初步），等排期 | 对应模块推进器 / 主会话 |
| 落实中 | 推进器轮次或主会话进行中 | 对应模块推进器 |
| 待验证 | 代码已改，等冒烟/真机验证 | 对应模块推进器 |
| 已解决 | 验证通过 | 回写提交号后置此态 |
| 已搁置 | 附理由（不阻塞／依赖其他项／等主人拍板） | 主会话 |

## 四、收集与优先级约定

- 本群内任何反馈织卷问题的消息都算反馈（一句话、截图都行）；**收到当天落档**，分类 24h 内完成。
- 严重度：**P1**＝挡路/数据风险/明显 bug → 主会话当场优先修；**P2**＝体验/效率问题 → 对应模块推进器下一轮（≤4h）；**P3**＝锦上添花 → 低优先级排队。
- 反馈原文太长时在「反馈要点」写压缩转述，保留原始消息时间；截图类反馈附图片路径（`/Users/USER/.hermes/cache/images/…`）以便复现。
- 每条解决后：本清单回写「处理」列（提交号＋验证结果），模块推进器当轮回执里一句话带过。
