# 正文写入与切片同步 · 口径（2026-09-13 创作层定稿）

> 本文是「正文写入 → 切片同步」链路的**权威口径**（代码事实 + 设计意图），后续改动此处为准。
> 上游设计：模块设计-V2 §6.5（保存 → 时间切片同步）；正文为源、设定为流。

## 1. 不变式（任何改动不得破坏）

1. **正文为源、设定为流**：正文变化是设定流的唯一驱动；同步产物**只出提案，绝不改正文**。
2. **写优先**：同步失败 / LLM 不可用只影响「设定沉淀」，绝不影响正文写入本身（模块设计 §6.6）。
3. **仅正文触发**：只有 `正文/` 前缀的写入触发切片同步；人物/世界观/素材/大纲审读等一律不触发（设定文档走提案制，其内容变化本身就是提案写入的结果）。
4. **约定头是唯一半结构化约定**：切片名/涉及人物取自章首 front matter（`切片`/`涉及人物`），同步装配据此组包。

## 2. 五个写入入口与触发口径

| # | 入口 | 触发点 | 调用 | 60s 节流 | 同步结果呈现 |
|---|---|---|---|---|---|
| 1 | **保存正文** | Novel.tsx `handleChapterSaved`（DocEditor onSave，Cmd+S/失焦） | 直调 `runSliceSync` | **不过**（显式动作，每次必同步） | 正文页浮动提示「✓ 已生成 N 条切片提案 / 无设定变化 / ✗ 失败」 |
| 2 | **分幕采纳** | Outline.tsx `adopt`（`doc:adoptActs`，整章替换） | 直调 `runSliceSync` | **不过**（显式动作） | 大纲区 msg + toast（「切片同步中…」→ 结果） |
| 3 | **EditCard 采纳** | AgentPanel.tsx `accept`（`doc:applyEdit`，模型 zj_edit_doc 修改卡） | `syncAfterChapterEdit`（收口） | **过** | 修改卡底部小字（成功/失败/「本分钟内已同步，不重复」） |
| 4 | **批注提案接受** | ProposalDrawer.tsx `doApply`/`allApply`（`applyProposal`，kind=replace-text） | `toastAfterChapterApply` → 收口 | **过** | toast「正文已改写，切片同步到 N 条提案待确认」 |
| 5 | **历史版本恢复** | HistoryDrawer.tsx `restore`（`writeDoc` 回写旧版） | `syncAfterChapterEdit`（收口） | **过** | 抽屉 msg（「✓ 已恢复；切片同步…」） |

### 节流口径（关键设计意图，勿一律化）

- **入口 1/2 不过节流**：保存/采纳是用户**显式、逐次的**动作，每次都必须重新比对——60s 内连续保存两次，第二次也要出提案（用户刚写入的新事实不能因节流被吞）。
- **入口 3/4/5 过节流（60s 同文件）**：一次对话里连续采纳多条 edit / 批量「全部接受」多条批注提案 / 连续恢复，属于**同一批写入**——只烧一次引擎，重复比对无增益。入口 4 的 allApply 对多个不同文件分别触发（按 target 去重，各自有独立 gate key）。
- 节流由 `syncAfterChapterEdit` 统一执行（key = `projectId|rel`）；**失败 `gate.clear()` 不节流**——用户再触发（再保存/再恢复）可重试，不会因上次失败被锁 60s。

## 3. 收口函数契约（`features/sync/editSync.ts`）

```ts
syncAfterChapterEdit(projectId, rel): Promise<SliceSyncResult | 'skipped' | 'throttled'>
```

- `'skipped'`：rel 非 `正文/` 前缀（人物/世界观/大纲审读等）——调用方静默返回。
- `'throttled'`：60s 窗口内该文件已同步过——调用方展示「本分钟内已同步，不重复」类文案，**不视为失败**。
- `SliceSyncResult`：`ok / items / issues / error`（issues＝产物守卫拦截/纠正记录，有内容即需作者知道的处置）。

判定 `isChapterTarget(rel)` 在 `shared/editSyncGate.ts`（纯函数，`rel.startsWith('正文/')`），单测覆盖。

> **勘误**：`editSync.ts` 头注释与 09:45 轮日志曾写「全部入口都走收口+节流」——**不准确**。真实口径：只有 3/4/5（自动/批量写入）走收口过门，1/2（显式动作）直调不过门（见上表）。已按本文修正注释。

## 4. 触发后的完整链路

```
写入完成（writeDoc/applyDocEdit/applyProposal/…）
  └─ [1/2] runSliceSync(projectId, rel) ／ [3/4/5] syncAfterChapterEdit
       └─ window.zhijuan.agentSync（主进程：装配上下文 → 引擎跑「切片同步」子任务）
            ├─ 读本章约定头 → 切片名 + 涉及人物
            ├─ 装配：本章正文全文 + 基准（上一切片人物状态/世界观切片文件，无则总纲）
            └─ 产出结构化「切片同步提案」JSON（目标文件/锚点/拟写内容）
       └─ guard 产物守卫（target 存在性防线，拦截/纠正记录进 issues）
       └─ createProposals(projectId, 'slice-sync', chapterRel, slice, items)
            └─ 落盘 .zhijuan/proposals/<id>.json → 顶栏「待确认 N」亮起（store bump）
```

- 同步结果文案统一口径：`items>0` →「已生成 N 条切片提案」；`items===0` →「无设定变化」；失败 →「✗ …（可稍后在正文页再保存一次触发）」。
- 入口 1 有并行前置快检（`checkChapterUnlisted`/`checkChapterMissing`，零模型：正文出现档案本名但约定头未列 / 列了未达到最小字数未出现 → 汇总提示卡），**只挂保存入口**，其余入口不复用（语义是「约定头与正文的不一致」，仅保存时点有意义）。

## 5. 失败与恢复

- 引擎不可用/超时：`SliceSyncResult.ok=false`，正文已写入不受影响（写优先）。
- 「同步失败」后用户可：在正文页再保存一次（入口 1 不受节流影响）、或重新接受/恢复（入口 3/4/5 因失败 clear 不节流，可直接重试）。
- 提案过时（正文又改）：由提案系统 stale 机制处理（before 锚点校验，原文已变标记 stale「请人工确认」），与同步链路无关。

## 8. 切片名修改与同步（2026-09-13，4867b74 收口）

### 8.1 入口与语义

- 章节右键「修改切片名」→ `chapter:editSlice` → `store.editChapterSlice`：正文约定头 `切片` 字段改写（`setFrontMatterField`，走 writeDoc → 版本化快照，可回退）。
- 切片名是**切片归属键**：同步装配/写入的人物状态小节与世界切片文件名都带切片名（§4 链路读的是约定头 `切片` 字段）。

### 8.2 引用面收口（编辑时一次性完成）

| 面 | 动作 |
|---|---|
| 正文约定头 `切片` | 唯一权威处，改写（版本化） |
| `大纲/` 同名写作副产物（章卡/导演板/分幕）fm `切片` 字段 | best-effort 同步（`syncChapterSliceInDoc`，与题名同步同款遍历） |
| 该章 slice-sync **pending** 提案 | 置 stale（`staleSliceSyncByChapter` 按 source 收口——annotation-sync 等与切片名无关的保留 pending），防旧名提案按旧名落盘 |
| 世界切片文件 `世界观/切片_<旧名>.md`、人物档旧「## 切片：<旧名>」小节 | **保留为历史**（时间切片语义：旧切片是已发生时刻，不自动搬家/改写；作者手工编辑过的文件不动） |

### 8.3 与同步链路的关系（关键口径）

- **编辑动作本身不触发 runSliceSync**（改名 ≠ 正文变化）。
- 新切片名下的设定流由「正文为源」触发：**下次保存正文（入口 1，不过节流）** 时引擎按新切片名装配基准并生成新提案；旧切片设定保留在历史文件中（§8.2），模型仍可按章节上下文读取。
- **（2026-09-14 真模型端到端已验证，scripts/slice-rename-live.mjs，18 断言全过）**：改名后 runSync 按约定头**现读**新名装配（ensureWorldSliceFile 建 `切片_B.md`、锚点归一「切片：B」、产物无旧名 target/anchor——无陈旧缓存）；旧 `切片_A.md` 保留原样且**不入新上下文**；人物档新旧切片小节并存（§8.4 已知口径）。

### 8.4 已知观察（登记备查，真实使用触发再评估）

- 人物档新旧名切片小节并存＝同一时间点两版小节，注入上下文时旧名小节可能被当作另一时间点——改名场景固有语义（业界无解），不处理。
- 世界切片孤儿文件 `切片_<旧名>.md` 无提示——历史保留为设计语义；若真实使用觉得碍事再做（提示/归档）。
- 涉及人物字段无独立编辑入口（仅保存前置 quick-fix）——与切片名同构的候选；无真实反馈不主动加。
