# 织卷 · V2 架构设计（主人 2026-09 定稿方向）

> 本文是织卷 V2 的架构权威源。V1（M1 要素引擎 + M2 导演引擎）仍是既有资产，本文明确新方向的定位、信息架构、数据方案，以及与 V1 的衔接（衔接细节见文末「待拍板决策」）。
> 原则：**泛化性优先** —— 架构不绑定任何具体题材、任何具体作品流程；时间切片、素材库、agent 协作是通用能力。

## 一、定位与原则

1. **泛化**：织卷是通用 AI 辅助创作工作台，不参考主人任何进行中的具体项目（都市短篇合集等）；所有能力按“任意题材、任意篇幅、任意叙事结构”设计。
2. **核心诉求**：**素材库积累** ＋ **面向时间切片的人物 / 世界观 / 环境设定**。长文不失忆的本质是“每个时间点的世界状态都被记录并可召回”。
3. **第一期全文档**：人物设定、世界观设定、环境设定、素材库一律以**文档（markdown）**形式维护，**不做结构化存储**。结构化留给文本本身自带的约定（见数据方案）。
4. **正文为源、设定为流**：正文是创作本体；设定是随正文推进而回填、同步的“切片快照”。保存正文 → 触发当前时间切片的其他设定按正文内容更新。
5. 延续 V1 原则：数据纯本地、明文、可入 git，作品永不锁死在工具里。

## 二、顶层信息架构

```
首页（项目管理页面）
  ├─ 项目列表（新建 / 打开 / 删除 / 导入）
  └─ 进入某项目 → 左侧边栏四大板块：
       ├─ 正文创作     （markdown 编辑器 + 右侧 agent 区域）
       ├─ 人物设定     （文档式）
       ├─ 世界观设定   （文档式）
       └─ 素材库       （分类文档 + 联网采集入口）
```

- 一个项目 ＝ 一部作品的完整工作区，对应一个项目目录。
- 侧边栏四大板块是每部作品的标准结构；板块之间通过**时间切片**联动。

## 三、时间切片模型（核心）

**切片的定义**：正文的每个章节都绑定一个**时间切片**（故事内时间的一段）。每个切片承载该时刻的：

- 人物状态（在场角色、关系变化、身体/心理状态、知晓的信息）
- 世界观状态（被揭示的规则、发生的事件、环境变化）
- 环境状态（地点、器物、当刻风物）

**联动规则**：

1. 章节头部带一小段**约定头**（front matter）：章节名、所属时间切片、涉及人物。这是第一期唯一的“半结构化”约定，本质仍是文档。
2. **保存正文** → 按当前章节的约定头定位其时间切片 → 触发 agent 基于正文推导并**更新该切片的其他设定**（人物 / 世界观 / 环境），保证设定永远与已落盘的正文一致。
3. 设定可以**向前写**（细纲先定切片状态），但任何一次正文保存都以“正文为准”回填该切片。

## 四、数据方案（第一期：纯文档）

```
织卷项目库/
  <项目ID>/
    project.md            # 项目封面：简介、时间线总纲、切片清单、约定说明
    世界观/
      总纲.md             # 时代、舞台、规则、主题等长期不变部分
      切片_<切片名>.md    # 每切片的当刻世界状态（按需创建）
    人物/
      总览.md             # 角色目录 + 谁在哪切片出场
      <角色>.md           # 角色静态档案 + 「各切片状态」小节（保存正文时 agent 增量更新）
    正文/
      第NN章.md           # 带约定头（章名/时间切片/涉及人物）
    素材库/
      索引.md             # 分类目录
      <类别>/…            # 按类别维护的素材文档
      采集池/             # 联网采集的任务与原始材料（见第六节）
```

- 约定头用最简格式（如 YAML：章名、切片、人物），便于程序定位且人可直接读、直接改。
- 除约定头外，一切正文自由书写，不做 schema。

## 五、正文创作与 agent 区域

- **正文创作页**：中部 markdown 编辑器 ＋ **右侧 agent 区域**（对话式），传统生成按钮**不是**主通道，主通道是边聊边生成。
- **选中即引用**：可在编辑器选中任意一段 → “引用到 agent 对话”，agent 基于该段回答 / 改写 / 续写，结果可回填文档。
- **相关设定都在 agent 下**：agent 的上下文默认携带当前章节 + 其时间切片的设定 + 涉及人物档案 + 素材库索引；且 agent **可以读写**人物 / 世界观 / 素材库文档（保存正文时的切片回填就是 agent 在写）。
- 改动的落实方式（直接改 or 先出提案再确认）见待拍板决策。

## 六、素材库与联网采集

- 素材库是**项目级**资源（与时间切片正交），按类别以文档维护，供所有切片取用。
- **按需求采集**：素材库页提供“采集需求”表单（关键词 / 用途 / 来源偏好）→ 生成一条采集任务（落在 `素材库/采集池/`，或一条带状态的卡片）→ 由**本机采集管道**执行（复用已就绪的 web 栈：searxng 检索 + 专用浏览器/FlareSolverr 过墙）→ 清洗后按类别入正式库，并在任务卡上回填结果。
- 第一期 App 与采集管道的通道用**约定目录 + 后台处理**（App 写任务，后台接管并回填），App 自身零网络依赖；成熟后再考虑内嵌。

## 七、与 V1 的衔接（待拍板）

## 九、V2 技术选型与 UI 设计语言（2026-09 定）

- **UI 框架**：Tailwind CSS v4 + **shadcn/ui**（Radix 基座）——现状是裸 React，这是当前最具备设计美感且可深度定制的组合。
- **编辑器**：**Milkdown**（ProseMirror 内核 WYSIWYG markdown 编辑器）——支持自定义命令，可落地“选中段落 → 交给 agent”。
- **设计语言**：**暖纸面（Notion 系）为主、精密中性铬（Linear 系）为辅的混合**。默认浅色暖调，画布像纸；应用框架走中性灰、细发丝边框、单一强调色。详细 tokens 见 docs/模块设计-V2.md。
- 其余：react-markdown（agent 回复渲染）、lucide-react（图标）、zustand（轻量状态）。
- 详细模块设计与实现里程碑见 **docs/模块设计-V2.md**（新模块权威源）。
