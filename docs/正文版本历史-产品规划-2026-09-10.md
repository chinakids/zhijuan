## 一、需求与为什么现在做

- 织卷正文是唯一源：`writeDoc` 覆盖写盘，改坏了或想回到某版，目前无处可回——只有切片同步提案里保留旧片段（且那是设定侧，不是正文侧）。
- 大验收（写完 5 万字且自洽）路径上，「改稿/回退」是写作常态；没有历史，主人只能靠手动备份或外挂 git。
- M3 菜单项已立项（ROADMAP），但方向未定——先统一形态再做，避免做完再返工。

## 二、业界形态调研（来源均为官方一手页，2026-09-10 抓取）

| 形态 | 代表 | 形态要点 | 结论 |
|---|---|---|---|
| 手动快照 | Scrivener Snapshots（literatureandlatte.com/scrivener/overview：「take a Snapshot of a section and you'll be able to return to the earlier version whenever you want… The Compare feature will show you」） | 重大修改前手动拍照，可回档，Compare 显示差异；按文档节粒度 | 面向「人主动留档」，不覆盖日常保存 |
| 自动 git | obsidian-git（github.com/Vinzent03/obsidian-git README：自动 commit-and-sync 定时、History View、diff；配 Version History Diff 插件做文件级历史） | git 驱动，适合同步型笔记库；作者建议大 repo 分级暂存 | 依赖 git 环境；与用户自管 git 可能冲突/嵌套 |
| 自动本地历史 | JetBrains Local History（jetbrains.com/help/idea/local-history.html：自动记录每次有意义修改、独立于 VCS、可搜索/对比/回滚；**明示非 VCS 替代、有 retention 与最大尺寸、升级会清空**） | IDE 内短期安全网 + 恢复源 | 关键取舍：自动记录 + 保留上限 |

- Novelcrafter 文档（Getting Started）未见版本历史功能；其 Codex Progressions 是自动覆盖型（前轮已核）——织卷与其不同，坚持纯文件+提案制，版本历史做成**可审计的快速档**。

## 三、拍板方案（本推进轮决策，属小到中取舍，直接落地）

**自动快照制** = Scrivener 快照 + JetBrains 自动记录的混合：

1. **触发**：正文保存时（唯一写入口 `store.writeDoc`）落盘前，若目标文件已存在且内容不同 → 把**旧内容**存档为一版。文件本身即最新版，历史永远指向过往瞬间（回滚即取任一版写回）。
2. **范围**：仅 `正文/` 前缀文档（模块应用约定=章节正文）。人物/世界观改动走提案制（锚点+提案文件本就是审计轨迹）；大纲/导演板是写作副产物；其他目录不产生历史噪音。
3. **存储**：`.zhijuan/history/<rel去掉.md>/<yyyyMMdd-HHmmss-SSS>.md`（保留原目录层级避免同名冲突）。纯明文、零依赖、可随项目入 git 或由用户 gitignore。
4. **保留**：每文件 50 版（常量 `HISTORY_LIMIT`），超限删最旧。不做时间窗合并、不做设置化（默认值先跑起来，再按真实使用调）。
5. **不依赖 git**：项目库可能不是 git 仓库；用户自管 git 时快照与 git 互不干扰（快照是补充安全网，不是 VCS 替代——JetBrains 同款结论）。

### 不动什么 / 不做什么

- 不动 proposals 数据结构、切片同步、约定头；不改任何 UI。
- 不做：diff 对比视图、恢复按钮、历史入口 UI、手动快照按钮、设置化（均为后续轮次，见「四、验收」）。
- 不引第三方依赖（文本 diff 后续用轻量实现，本轮没有 UI 无 diff 需求）。
