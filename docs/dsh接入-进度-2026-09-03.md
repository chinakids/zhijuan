## ⚠️ 关键坑（新手上手先看）

- **SDK 高层 `session.run()` 在同 session 续轮时只回放历史、吃掉实时正文**：事件该来不来，`finalResponse` 为空。**绕法：自己用低阶 HarnessClient 驱动**（`driveSession`：subscribeSessionTree + prompt + 按 turn 圈定结束），事件全量可见，还天然支持提前退出。
- **session.event 的 type 在 envelope 上**（`event.type`），不是 data；data 才是具体字段。用错层级会“看不到事件”。
- **会话模型定为每轮新 session id**，历史由渲染层带进 prompt（≤20 条）。优点：绕开续轮坑、上下文完全可预算、可随时截断。**代价**：模型没有隐式记忆，长对话靠历史注入。
- 工具循环：模型查资料时 step 可能较多（sync 那次 11 步），本地模型速度尚可；后续可给 prompt 加“最多调用 N 次工具”预算。

## 🧪 无头全栈真机验收（2026-09-03 晚间 · 锁屏状态）

**锁屏实测**：真 Electron 三种起法（正常、`--disable-gpu`、`--headless=new`）都是**主进程可起、renderer 建不出**（卡在渲染子进程）→ 锁屏下无可视窗口、无 CDP。屏锁时全栈验收只能用无头套路。

**bridge 方案（新增 `scripts/zj-bridge.mjs`）**：把页面里的 agent 请求接到**真主进程引擎栈**（边车 + 真模型 + zj 工具读真文件），事件按 harness 协议回传。做法：esbuild bundle `src/main/agent/engine.ts` → node 跑（alias electron=electron-stub）→ 开本机 WS :8810；无头页面里注入桥接片（把 `window.zhijuan` 的 agent 通道换成走 WS，`agentSend` 等整轮 done 再 resolve，与真机 `ipcMain.handle(runChat)` 语义一致；事件同时喂进 devShim 的 `agentListeners`，面板收得到）。**只换通道，不改一行生产代码。**

**验收结果（页面真模型对话 ✅）**：无头 Chrome 打开真实渲染产物 → 进项目 → 注入桥接 → 发“用 zj_read_doc 读当前章节+世界观，说核心冲突”。模型**真调了工具**（首调参数格式有误被拒 → 自纠重读），流式输出内容**贴合真实设定文件**（林晓守旧约等船、灯嫂的孙女、陈默缉私线），结束 `done` 后「生成中…」正确清除。页面 → 桥 → 引擎 → 边车 → 模型 → 事件回传，全链路真实跑通。
