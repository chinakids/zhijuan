# 章节导演助手（V1 导演引擎回接第一步）· 进度 2026-09-07

> 依 D-V2-1（V2 一期 S1–S6 成型后回看 V1 能力回接）与架构评审 E3（『教程助手 / 导演助手』等新助手按 E1 骨架 + 能力注册表落地）推进。

## 做什么（一行）

**章节导演**：动笔前先用写作引擎给一章导出「导演板」——情绪弧分段 + 每段戏剧任务 + 波峰定位 + 涉事人物行为轴 + 写作红线 + 要还的钩子——随章卡一起落 `大纲/<章>_导演.md`。

## 为什么这样设计（拍板理由，文字>大脑）

1. **这是 V1 导演引擎在 V2 里的正确落点**：V1 的导演板/分幕/行为轴是「给一章写什么定方向」，本质上是对**将要写的章**做的导演，天然属于「先设定后成文」；V2 一章一切片，导演板就是这一章切片在动手前的设定之一。
2. **素材唯一入口**：直接复用 `buildWritingContext`（当前章要素块 + 上一章尾部 + 涉事人物档案 + 当前切片 + 章卡），与 runChat / runSync 同一创作半径，一条装配多处消费，不新造一套上下文。
3. **落点选 大纲/**：导演板是写作副产物（与章卡同一约定直写），不是设定本体；设定推进才走提案制。
4. **V1 术语沿用**：戏剧任务四档（推进/白热化/拉锯/低谷）、人物行为轴电平（被压/试探/放开）继承 V1 导演语汇，为后续把 V1 的更完整导演能力（分幕、兑现检查）回接留好接口。
5. **走子任务骨架**：subtask 定义 + 能力注册表（设置页自然出现「章节导演」开关）+ retry 加固，与 S6 四件套同构，不新写样板。

## 导演兑现检查（2026-09-08，导演板「有牙齿」的收尾）

**做什么（一行）**：正文写完后，用写作引擎对照本章导演板逐项核对：情绪弧分段 done/partial/missed、行为轴 aligned/drifted/absent、红线 kept/broken、钩子 paid/open/new，输出 summary + 各四类核对条目，经 IPC 回 UI（大纲区顶部「兑现检查」按钮 → 抽屉展示），**只读不改稿、不落盘**（导演板才是落盘副产物；检查结果是给作者的瞬时报告）。

**为什么这样设计（文字>大脑）**：
1. 这是「先设定后成文」闭环的**收尾校验**：设定（导演板）→ 约束成文（runChat 随行注入）→ 兑现核对（本功能）三步成环，导演承诺要么落地要么被明确看到落差，正是 V1 M2.4 兑现检查在 V2 的正确落点（基准从 V1 的曲线换成了 V2 的导演板分段，导演语汇继承）。
2. **只读不写**：与本检查是同族但不同约定——导演板是写作副产物直写盘；检查结果是瞬时报告，落盘只会堆脏文件，故回内存给 UI。
3. **复用骨架与素材纪律**：走 runSubtask + 能力注册表（设置页自然出现「导演兑现检查」开关）；材料只给 导演板 + 本章正文（clip 截首尾），不再叠 buildWritingContext 全量装配——核对的基准就是导演板本身，保持请求小而准；axes 人物仍用本章涉及人物做白名单防编造。
4. **结构化 JSON 两道加固沿用**：提示词写死「整个回答只能是这个 JSON 对象」；extract 空结果自动 retry 一次（先写左花括号）。

**实现**：src/main/agent/director-check.ts（directorCheckDef → runDirectorCheck，extractDirectorCheck 各状态白名单清洗 + 条数上限）+ ipc agent:directorCheck + preload agentDirectorCheck + devShim 演示 + 大纲区「兑现检查」按钮与 DirectorCheckDrawer；单测 tests/unit/director-check.test.ts（9 例）。

## 导演板偏旧提示（2026-09-08，兑现检查的护栏）

**做什么（一行）**：大纲区里若某章的导演板比它的正文更旧（正文在导完板子之后又被改过），侧栏该章「导演板」子项给出「偏旧」角标；选中该章时，主区顶栏下方出一行轻提示：「本章导演板早于正文：兑现检查对照的是旧承诺，正文有改动建议点『导演本章』重导。」

**为什么这样设计（文字>大脑）**：
1. 兑现检查对照的是导演板；若正文在导板之后又被改过，检查结果对照的是旧承诺，容易误导作者以为「没问题」。这层提示让「先设定后成文」闭环的收尾不被静默地建立在过期设定上。
2. **纯渲染层、只读**：新旧判断只要文件 mtime 对比（正文用 listChapters 的 mtime，导演板用 listDocs 大纲的 mtime），不动主进程、不加模型调用、不改文件；判据是一行纯函数 `isBoardStale(boardMtime, bodyMtime, tolerance)`（src/shared/boardAge.ts，容差 5s 兜同一轮写好刚保存的顺序抖动）。
3. UI 面轻：角标复用现有 warn 角标风格（同「待回建」），顶栏提示一行、可随正文再保存后的 fs 事件随 refresh 自动消失。

**实现**：src/shared/boardAge.ts（isBoardStale + 容差常量，可单测）+ Outline.tsx 的 staleBoards 集合与两处 UI（侧栏角标 + 顶栏提示），refresh 保留大纲 mtime 映射；devShim 把 `_导演` 文件的 mtime 模拟成一天前并补种第01章演示导演板，让演示页自然出现该提示；单测 tests/unit/boardAge.test.ts（4 例）。

**顺带修的渲染层崩溃（8a11cc6 带入）**：兑现检查按钮的 title 用 `hasBoard(selChapter!)` 非空断言——当左侧选中项不是章卡（默认就是「章卡索引」）、selChapter 为 null 时，把空值传进 boardRel → `null.name`，整页大纲区白屏（dev 直接复现）。已改三层：title 先判 selChapter 再 hasBoard，未选中时给「先在左侧选中一章」。**教训：带上层 title 里的非空断言也要真机验证，光 typecheck 绿不住运行时。**

## 分幕生成（2026-09-08，V1 逐幕生成在 V2 的落点）

**做什么（一行）**：有了导演板的章，点「分幕生成」＝把全章按导演板情绪弧分段**逐段**交给写作引擎成文——一段一个**独立请求**（真正的外部续写上下文：前段末文原样带进下一段 prompt），本段戏剧任务是这段的**硬指令**，全章红线每段都带；边写边把上一段结尾收进下一段开头，最后把各段拼成**本章定稿草稿**落 `大纲/<章>_分幕.md`。

**为什么这样设计（文字>大脑）**：
1. **这是 V1 M2.2「逐幕生成」在 V2 的正确落点**：V1 短板的原话是「曲线只是参考建议——一次性生成整章，长度一上去曲线契约就在中间流失」。分幕正是把“一次写完”拆成“一段一段写、每段都带自己的戏剧任务并把前段末文当续写上下文”的外部机制，让导演板的曲线契约从「随行注入的参考」变成「逐段的硬约束」——「先设定后成文」从设（导演板）→ 约束（随行注入）→ 核对（兑检）之后，补上了**成文这一步的真实控制力**。
2. **草稿不进正文**：正文仍是作者的地盘，改正文始终走 zj_edit_doc → EditCard 的采纳口径；分幕产物是写作副产物（与章卡、导演板同约定，直写 大纲/），作者在左栏点「分幕草稿」查看、认可后自行把正文搬进正文文件。后续再加「采纳为正文」按钮（整稿走 doc:applyEdit）把这一步也接起来。
3. **请求小而准、不叠 buildWritingContext**：每段材料＝本段指令（task+goal+波峰标注）＋全章红线＋前段末文（或板子的章节前情）——与 director-check 同纪律：基准就是导演板本身。首段不拉上一章尾部：板子的 premise 本来就是 buildWritingContext 喂出来的，已编码足够前情，v1 先不重复装配。
4. **复用骨架**：每段一次 runOnce（同 outline 的循环做法），整体能力「分幕生成」进能力注册表（设置页可开关）；runActs 传可选 maxActs 仅供调试/冒烟限段。

**实现**：`src/shared/boardParse.ts`（parseDirectorSheet：导演板 md → 结构化，纯函数可单测，供分幕及各消费方直接拿分段做事）+ `src/main/agent/acts.ts`（actDef + runActs，逐段 runOnce，前段末文 TAIL=900 字带进下一段；段短于 120 字自动重试一次；拼装保留原章约定头并标 `状态: 分幕草稿`）+ ipc `agent:acts` + preload `agentActs` + Outline.tsx「分幕生成」按钮与左栏「分幕草稿」子条目（章数统计与选中映射都排除 _分幕 文件）+ devShim 演示（有板子才可点，写入演示草稿）。

**边界与取舍（有意为之）**：
- 分幕草稿只证明「逐段生成的控制力」，成品质量要作者在正文里把把关——它只是草稿，不走「写完一章就算成稿」的任何中间态。
- 首段前情用板子 premise，不拉上一章尾部（板子已由 buildWritingContext 装配过前情）；若后续发现接续感弱，可在首段补「上一章尾部」这一块材料。
- 波峰只标出段落，波峰事件由模型按板子指令正面写（板子里波峰 idea 已给出）。

**验证**：三道门全绿（typecheck / build / 99 例单测，新增 12 例：parseDirectorSheet 4（round-trip、手写板子、空串容错、条数上限钳制）、actPrompt 3、buildActsDoc 1、runActs 4（章缺、无板、全流程三段+前文承接带套、能力关闭拦截））；真模型冒烟 scripts/acts-smoke.mjs（织卷smoke 第02章，按现有导演板前 2 段逐段起草并落盘回读实锤）。
