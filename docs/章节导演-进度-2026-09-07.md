# 章节导演助手（V1 导演引擎回接第一步）· 进度 2026-09-07

> 依 D-V2-1（V2 一期 S1–S6 成型后回看 V1 能力回接）与架构评审 E3（『教程助手 / 导演助手』等新助手按 E1 骨架 + 能力注册表落地）推进。

## 做什么（一行）

**章节导演**：动笔前先用写作引擎给一章导出「导演板」——情绪弧分段 + 每段戏剧任务 + 波峰定位 + 涉事人物行为轴 + 写作红线 + 要还的钩子——随章卡一起落 `大纲/<章>_导演.md`。

## 为什么这样设计（拍板理由，文字>大脑）

1. **这是 V1 导演引擎在 V2 里的正确落点**：V1 的导演板/分幕/行为轴是「给一章写什么定方向」，本质上是对**将要写的章**做的导演，天然属于「先设定后成文」；V2 一章一切片，导演板就是这一章切片在动手前的设定之一。
2. **素材唯一入口**：直接复用 `buildWritingContext`（当前章要素块 + 上一章尾部 + 涉事人物档案 + 当前切片 + 章卡），与 runChat / runSync 同一创作半径，一条装配多处消费，不新造一套上下文。
3. **落点选 大纲/**：导演板是写作副产物（与章卡同一约定直写），不是设定本体；设定推进才走提案制。
4. **V1 术语沿用**：戏剧任务四档（推进/白热化/拉锯/低谷）、人物行为轴电平（被压/试探/放开）继承 V1 导演语汇，为后续把 V1 的更完整导演能力（分幕、兑现检查）回接留好接口。
5. **走子任务骨架**：subtask 定义 + 能力注册表（设置页自然出现「章节导演」开关）+ retry 加固，与 S6 四件套同构，不新写样板。

## 导演兑现检查（2026-09-08，导演板「有牙齿」的收尾）

**做什么（一行）**：正文写完后，用写作引擎对照本章导演板逐项核对：情绪弧分段 done/partial/missed、行为轴 aligned/drifted/absent、红线 kept/broken、钩子 paid/open/new，输出 summary + 各四类核对条目，经 IPC 回 UI（大纲区顶部「兑现检查」按钮 → 抽屉展示），**只读不改稿、不落盘**（导演板才是落盘副产物；检查结果是给作者的瞬时报告）。

**为什么这样设计（文字>大脑）**：
1. 这是「先设定后成文」闭环的**收尾校验**：设定（导演板）→ 约束成文（runChat 随行注入）→ 兑现核对（本功能）三步成环，导演承诺要么落地要么被明确看到落差，正是 V1 M2.4 兑现检查在 V2 的正确落点（基准从 V1 的曲线换成了 V2 的导演板分段，导演语汇继承）。
2. **只读不写**：与本检查是同族但不同约定——导演板是写作副产物直写盘；检查结果是瞬时报告，落盘只会堆脏文件，故回内存给 UI。
3. **复用骨架与素材纪律**：走 runSubtask + 能力注册表（设置页自然出现「导演兑现检查」开关）；材料只给 导演板 + 本章正文（clip 截首尾），不再叠 buildWritingContext 全量装配——核对的基准就是导演板本身，保持请求小而准；axes 人物仍用本章涉及人物做白名单防编造。
4. **结构化 JSON 两道加固沿用**：提示词写死「整个回答只能是这个 JSON 对象」；extract 空结果自动 retry 一次（先写左花括号）。
