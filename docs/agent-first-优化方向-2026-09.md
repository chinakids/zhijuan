# 织卷 · agent-first 优化方向（2026-09 定，2026-09 当日起步落地）

> 主人定的基调：织卷是 **agent 产品**，优化是「用 agent 优势改写传统流程」，不是把老模具copy一遍。
> 本文件是方向稿 + 落地记录；每条后面标注实现状态。

## 定位一句话

> 不再是要你手动建大纲、苦记一致性的记录工具，而是：**在写作半径内永远记得前文、永远可以拿一个新视角重新看自己、把改稿压成十分钟**的 agent-first 写作工作台。

## 传统环节 → agent 化 

| 传统 | 为什么很久 | 织卷 agent 化 | 状态 |
|---|---|---|---|
| 搁笔冷静 2–4 周 | 等生理性忘细节 | **一键冷读**：写完即用“读者视角”通读，外部者说话 | ✅ 已实现（冷读报告） |
| 从头重读找问题 | 要人肉摸出生搬硬套 | **反打大纲+漂移清单**：agent 按设定档逐条对照正文，直接列差异 | ✅ 已实现（一致性巡查） |
| 自己写修订计划 | 专家经验 | **分层修订单**：故事/场景/词句分层，按清单逐层跑 | 🚧 下一步（P1） |
| 找 beta 读者（稀有） | 反馈难得且贵 | **多视角审视**：不同角色视角的 agent 通读 | 🚧 可做（P2） |
| 靠记忆力记一致性 | 长文头号痛点 | **常驻巡查**：基于设定档案的检查引擎 + 提案一建 | ✅ 已实现（可一键转提案） |

## 已实现（本轮，2026-09）

### 全卷检查子任务（src/main/agent/audit.ts）
- **一致性巡查 consistency**：主进程把全卷正文（按章截段）+ 全部设定档案整理为材料包 → 写作引擎一次结构化输出 JSON → UI 渲染“巡查报告”，每条：严重度、类型（设定冲突/时间线/伏笔/人物漂移）、位置、现象、建议、可选目标文件。
- **冷读报告 review**：同骨架，入口在 Agent 面板头部（盾牌 / 书图标），以资深编辑视角给整体判断 + 可操作发现。
- **每条可「转提案」**：目标文件存在时把建议做成 append 提案（进入提案抽屉，沿用“提案须经确认再写入”的安全写体系）。
- 见图：审计抽屉（一致性 + 冷读两 Tab）。

### 工作机制要点
- 与 runSync 同构：独立 session、无提问、纯离线；因此校验一致且可测试。
- **材料包化**而不是角色读：主进程自己读全卷截段放入 prompt，模型一次见钻别轮读文件，快且可控。

## 下一步（P0/P1 待讨论派单）
- **每章快闪检查**：写一章要不要做一步短巡查（用相同引擎但参数reduced、目标单章）——把“大巡查”折成沿写作线的小环。
- **分层修订助手**：冷读后按故事/场景/词句给出修订单，帮助不带经验的作者也能多轮打磨。
- **大纲区（章卡 + 细纲回填）**：让 agent 基于已有正文把章卡“回建”出来，画布活起来。
- **素材→设定升格助手**：采集池素材按语境归类并可“可入档与否”。

## 已实现（第二轮，2026-09-04 · 主人指示：四个候选一起做掉）

> 全部沿用「独立 session + 结构化 JSON + 材料包」骨架；每个结果都能沿安全路径落地（转提案 / 复制回正文）。

### 每章快闪检查（正文页「本章小环」）
- `runChapterCheck`（src/main/agent/audit.ts）：参数 reduced、目标单章——一章正文 + 设定档案小截段 → 写作引擎一次结构化 JSON，只列本章确有依据的刺点（设定冲突 / 时间线 / 伏笔 / 人物漂移），把大巡查折成沿写作线的小环。
- UI：正文页顶部「本章小环」按钮 → 抽屉（本章快查 / 分层修订两 Tab），可逐条转提案。

### 分层修订助手（同抽屉「修订」Tab）
- 同一引擎换系统提示：按 **故事层 story → 场景层 scene → 词句层 prose** 分层给修订单；每条带 layer 标签与能操作的改法（suggest）。
- 交互：按层分组展示；每条可「复制改法」回正文，或转提案（关联到设定文件时）。

### 大纲区（章卡 + 回建）
- `runOutlineRebuild`（src/main/agent/outline.ts）：逐章把已有正文回建成标准章卡（一句话定位 / 关键事件 / 人物进展 / 钩子），落到 `大纲/<章节名>.md` + `大纲/索引.md`；可只回建缺失章。
- UI：侧边栏新增「大纲区」板块；左列章卡清单（已回建 / 待回建），头部「回建缺失」「全部回建」，章卡在编辑器里可继续编辑。
- 章卡是正文写作的副产物（写作输出），主进程直写；设定类改动仍走提案制。

### 素材→设定升格助手（素材库「升格助手」）
- `runMaterialTriage`（src/main/agent/triage.ts）：素材卡按语境逐条归类（沿用已有类别），判断 **可入档 promote / 可借鉴 reference / 暂不用 skip**，promote 时给出建议入档的现有设定文件。
- UI：素材库顶部「升格助手」按钮 → 抽屉，逐条「升格为提案」（走提案需确认再写入）。
- 防编造：模型只能在现有设定档案清单里挑 target，条目必须对应真实存在的素材文件。

## 已实现（第三轮，2026-09-09 · 审读存档）

> 调研来源见 docs/agent-调研与优化-日志.md（agent-native 长篇工具如何把 AI Review 结果做成项目持久资产）。

- **全卷审计结论自动落盘**（55eb47f）：一致性巡查 / 冷读报告 / 多视角审视跑完即写 `大纲/审读_<名>.md`（覆盖式、空结果也留档、盘写失败不阻断）；抽屉结果行显示「✓ 已存档」；大纲区侧栏新增「审读存档」分组，点击可回看（DocEditor）。
- 定位：审计结论从「一次性对话」变成项目可追溯资产——改稿后重跑对比、跨会话回看、git 可回溯，呼应「把改稿压成十分钟」。
- 边界：本章小环（chapter/revision）暂不落盘（高频重跑噪音大）；报告是写作副产物（主进程直写），设定类改动仍走提案制。
