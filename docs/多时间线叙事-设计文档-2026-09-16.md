# 多时间线叙事 · 设计文档（v1，2026-09-16）

> 来源：主人 2026-09-16 反馈「现在的产品设计支持单时间线叙事，无法支持多时间线叙事」，
> 并在确认后拍板：**多时间线叙事直接纳入 V2 一期范围（改验收口径，一期向后延）**（F-20260916-02）。
> 本文档是这一方向的设计权威源；与 架构设计-V2 / 模块设计-V2 冲突处以本文档为准并回改上级文档。

## 一、现状（已核实的事实，非推测）

V2 当前模型是**单主线**：

1. 每章一个时间切片（D-V2-2），章头约定头含 `章号 / 题名 / 切片 / 时间 / 涉及人物`（模块设计 §4.2）。
2. 切片枚举：`shared/slices.ts listSliceEntries`——按章号数值升序（`第N章` 正则），切片名缺省跳过；结果登记 `.zhijuan/slices.json`（正文为源，可重建）。
3. 切片为**全局单序列**：无「线」维度；时间线页（Timeline.tsx）按此单序一维渲染。
4. 人物/世界观文档按切片分节（`切片：<切片名>` 小节），状态单链演进；「到本章为止」= 章号顺序上的前驱。
5. 上下文装配（context.ts）取「当前章 + **上一章尾部** + 涉及人物档案 + 当下切片世界观 + 章卡 + 素材索引」——「上一章」= 章号相邻的上一章，无线内概念。
6. 审计（智能层）对「切片序号倒流」只按「可能是有意的插叙」容忍（medium），不是一等公民。

## 二、需求拆解：多时间线叙事的典型形态

| 形态 | 例子 | 对系统的共同要求 |
|---|---|---|
| A 双主线并行、最终汇合 | 君臣线/江湖线交错 | 章节声明归属线；两线各自按序演进 |
| B 多时域交错 | 过去线（回忆）+ 现在线 | 「上一章」必须取**同线前驱**，否则跨时域误承接 |
| C 同一时间多视角分线 | 事件 X 的 A 视角章 / B 视角章 | 人物状态按线分叉：同一人在两线状态不同 |
| D 平行/假设世界线 | 「如果当时……」支线 | 线是独立的状态演进域 |

共同需求收敛为三条硬能力：**① 章节可声明所属线；② 人物/世界状态按线分叉且互不覆盖；③ 「到本章为止」的推理（装配/同步/审计/时间线视图）按线内序进行。**

## 三、设计原则

1. 延续 V2 铁律：**正文为源**、markdown + front matter 约定、零结构化存储（索引可重建）。
2. **兼容优先**：老项目/老章节零改动、零迁移；缺省即「主线」。
3. **扩展不是推倒**：不动 切片文件命名（`切片_<名>.md`）、不动人物档案格式、不动提案制。
4. 系统只做**约定与推理**，不强制约束；一致性靠审计提示，不靠拦截。

## 四、核心模型（v1 提案）

### 4.1 概念「时间线（线）」

- 线 = 项目级实体，有名称（如 `主线`、`过去线`、`林晚线`）、可选一句话描述。
- **枚举来源 = 正文章头**：新增约定字段 `时间线: <线名>`（可选）。扫描正文 front matter 自动枚举线 → 登记 `.zhijuan/lines.json`（与 slices.json 同构、可重建）；project.md「时间线总纲」段为人读说明，不再承担数据职责。
- 缺省：未写 `时间线` 字段的章 = `主线`（老项目自然全部落在主线，零迁移）。
- 约定：切片名建议**全局唯一**（跨线使用加线前缀，如 `过去·第三幕`），系统不拦截；线内同名切片在时间线视图以「线·名」双标签显示，审计出提示。

### 4.2 章头约定（新）

```yaml
章号: 3
题名: 夏夜的信
时间线: 主线          # 新增：缺省=主线；同书可多条
切片: 第二幕_台风夜
时间: 2026 年 8 月某夜
涉及人物: [林晚, 顾知远]
```

一章 = **恰好一条线** + **一个切片**（D-V2-2 一章一切片不变；一章跨多线不做，避免复杂化）。

### 4.3 索引模型

`SliceEntry` 增加 `line: string` 字段（来自章头 `时间线`，缺省 `主线`）：
- `shared/types.ts` SliceEntry + `shared/slices.ts listSliceEntries` 解析透传；
- 排序口径：**线内按章号升序**（`noOf` 不变）；全局列表在线内序基础上按线分组展示。
- `slices.json` 条目携带 line；线上线可见性（Timeline 页）按 line 分组/筛选。

### 4.4 人物/世界观状态（关键：零格式改动）

人物/世界档案的每切片状态小节仍以**切片名**为键（`切片：<名>`）。由于切片名全局唯一且每个章节状态按「章→切片」一一映射，**同一个人物在两线的不同状态 = 不同切片名的人/档小节**，天然分叉、互不覆盖，无需改档案格式。系统只保证：
- 装配时按「本章所属线」取该线的状态下文；
- 审计「切片序号倒流/同名切片共用」改为**线内**判定。

### 4.5 各子系统改动口径（挂到模块）

| 子系统 | 改动 | 归属 |
|---|---|---|
| 类型/枚举/索引 | SliceEntry.line、listSliceEntries 透传、lines.json 枚举重建、slices:list IPC | 平台层 |
| project.md 模板 | 时间线总纲段改「多线可列举」示例；示例项目补多线章 | 平台层 |
| 正文保存/切片同步 | runSliceSync 感知章所属线（切片文件与人物小节命名不变，仅上下文与装配按线） | 创作层 |
| 上下文装配 | **「上一章尾部」= 同线内、本章之前的最近一章**（线内前驱，按章号）；多线提示（装配块注明「本章线=xx，同线前章=第N章」） | 创作层 |
| 建章向导 | 新增「时间线」选择（预填上一章线；可手输新线）；多章连写预填同口径 | 创作层 |
| 章卡/导演板 | 透传线名（章卡 front matter 加 `时间线`），不改格式 ✅（2026-09-17，29e4355；非主线才写字段，章卡/导演板/parse/devShim 同源） | 创作层 |
| 审计 | 切片顺序/同名检查按线内；新增「跨线切片名重复」提示 | 智能层 |
| 时间线页 | 一维 → 按线分组（线标签 + 筛选切换）；每线独立时间序；无线的老项目显示单线（零回归） | 体验层 |
| 章节列表 | 章项显示线徽标（多线项目；单线零打扰） | 体验层 |
| devShim | listSlices/listChapters 同口径加 line；冒烟种子含多线案例 | 各层 |

### 4.6 边界与不做（v1）

- 一章跨多线：不做（保持一刀切）。
- 线合并/拆分/重命名工具：不做（作者可改 front matter；改名引用面同步留二期）。
- 跨线人物状态迁移/复制工具：不做（人工）。
- 线元信息（色彩/图标/描述）持久化：仅 project.md 人读段，不做 UI 编辑（二期）。

## 五、验收口径修订（替换 D-V2-5）

> 原 D-V2-5：写完一个中篇且各切片设定与正文自洽。
> 新 D-V2-5（2026-09-16 主人拍板）：**写完一个中篇且含至少两条时间线交错叙事；两线各自的切片设定与正文自洽，人物状态按线分叉不串线；时间线视图可按线查看。**（交付演示项目由主人或推进器自建样例，不与保密小说项目混用种子。）

## 六、成本测算与排期

- 改动面：类型/枚举（平台层低危）→ 装配/同步（创作层中危）→ 审计（智能层低危）→ 时间线页/章列（体验层低危）+ devShim/单测/冒烟 + 文档。
- 估算：**约 6–8 个模块轮次**（口径：单轮中位 20–34 分钟 ≈ 一个小项；本轮为跨四模块的连贯改动，按每模块 1.5–2 轮 + 集成验收 1 轮）。周交付窗口下预计 **2 周内随验收窗口交付**（见 周交付窗口-机制-2026-09-16.md），不单独承诺日期。
- 顺序：模型层贯通（平台层）→ 创作层装配/向导 → 智能层审计 → 体验层视图 → 集成验收（三道门 + 多线冒烟 + 真机走查 + 截图）。
