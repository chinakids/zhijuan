## 一、背景与目标

主人 2026-09-17 提出：织卷 agent 应像 Hermes skill 一样使用「技能包」——带 front matter 的 markdown
指令/流程文件（含用途、触发词、步骤、可能附带的工具契约），agent 按需加载调用，把「该怎么做」沉淀为
可复用资产（例如「写床戏」「名字命名法」「倒叙开篇法」）。同批的另一条：定时学习用户写作习惯→沉淀
skill（默认关，与批注开关 annotationsEnabled 同口径）。

**本轮目标**：产出增量 1「运行层」的设计基线——技能包格式、存放位置、触发匹配、注入面、与既有的
`/命令槽位`（shared/commands.ts）和 `@引用`（shared/mention.ts + main/agent/refs.ts）的关系、与
Agent 双线（任务-01 上下文管理 / 任务-02 体验）的交叉面、验收口径。**本轮只落规划不落代码**
（下增量按周交付窗口口径开工；先文档后实现=「文字>大脑」）。

## 二、真实调研（来源记档，2026-09-21）

1. **Claude Code《Skills》官方文档**（code.claude.com/docs/en/skills，无头 Chrome CDP 9224 实抓 82,446
   字符，存档 /tmp/zj-skills-claude.txt）：
   - SKILL.md = YAML frontmatter + Markdown 正文；frontmatter 仅当首行就是 `---` 时被读取。
   - **字段全表**：name（display name，命令名默认取目录名）/ description（推荐，模型据此决定何时使用；
     与 when_to_use 合并在技能列表中截断至 1,536 字符以省上下文）/ when_to_use（触发短语/示例请求，
     追加到 description 并计入上限）/ argument-hint / arguments（具名位置参数，`$name` 替换）/
     disable-model-invocation（模型不可自动加载，仅手动 `/name`）/ user-invocable（仅模型可调，隐藏于
     / 菜单）/ allowed-tools / disallowed-tools / model / effort / context: fork / agent / background /
     hooks / paths（glob 限定激活范围）/ shell / metadata / license / compatibility ——**全部可选**。
   - **加载模型（关键）**：常规会话中**技能描述常驻上下文**（让模型知道有什么），**完整技能内容只在被
     激活时加载**（progressive disclosure）；子代理预载则启动即注入全量。
   - **触发矩阵**：默认=「你可调 + 模型可自动调 + 描述常驻、内容按需」；disable-model-invocation=true=
     「仅手动 + 描述不入上下文」；user-invocable=false=「仅模型 + 描述常驻」。
   - **生命周期**：激活时渲染后的 SKILL.md 作为**单条消息进入对话并留驻后续轮**（权限：allowed-tools
     只持续到下一消息）；Claude 不会重复读文件；内容相同再次激活=只加一句「已加载」注记，不同才重插；
     auto-compaction 会把已激活技能重挂（每个保留前 5,000 tokens，合计 25,000 tokens 预算）。
   - **技能列表预算**：skillListingBudgetFraction 或 SLASH_COMMAND_TOOL_CHAR_BUDGET 控制列表占用；
     低优先级条目可「仅名称」；每条合计截断上限 1,536 字符（可配 skillListingMaxDescChars）。
   - **命令名来源**：个人/项目技能=`目录名`；`.claude/commands/<name>.md`=文件名（无技能目录）；
     插件技能=frontmatter name（插件前缀命名空间）；技能文件位置决定显式调用名。
2. **Agent Skills 开放标准《Specification》**（agentskills.io/specification，CDP 实抓 7,122 字符，
   OpenAI/Anthropic 等共同推进）：
   - 目录结构：`skill-name/SKILL.md`（必）+ `scripts/`（可执行脚本）+ `references/`（按需文档）+
     `assets/`（模板/资源），其余任意。
   - frontmatter 必填：`name`（≤64 字符、小写+数字+连字符、须与目录名一致）、`description`
     （≤1024 字符、须写清「做什么+何时用」、**含具体关键词**帮助 agent 识别相关任务——官方示例明示
     「Use when the user mentions PDFs, forms, or document extraction」）。
   - 可选：license / compatibility（≤500 字符环境要求）/ metadata / allowed-tools（实验性）。
   - **Progressive disclosure 三层**：metadata（name+description，~100 tokens，启动常驻全量技能集）
     → instructions（完整 SKILL.md 正文，<5000 tokens 推荐，激活时加载）→ resources（scripts/references/
     assets 按需）。**主 SKILL.md 建议 <500 行**，细节移到独立文件。
   - 文件引用=技能根相对路径、保持一层深，避免嵌套引用链。
3. **OpenAI / Codex**（api.github.com 直连取 openai/skills 仓库 README，1,840 字符）：
   - `openai/skills` 仓库**已弃用**，指向 openai/plugins 与 developers.openai.com/codex/skills +
     agentskills.io（开放标准）——**三家（Claude/OpenAI/标准组织）归一于同一格式**（SKILL.md +
     frontmatter + 渐进披露），织卷按此格式兼容即得「导入导出」天然互操作（ROADMAP 导入导出 .md 需求）。
4. 本机内部参照：Hermes skill（本仓库工作流即其一）形态=front matter（name/description/正文指令/流程）
   的 markdown 文件、按需激活——与上述开放标准同构，织卷「技能包」=该形态的项目内落地。

**调研结论（创作/产品视角）**：业界三项共识——①技能=**作者资产**（方法论/流程/检查清单，如
Novelcrafter 的 prompt templates、Grammarly 个人词典同类的「个人化产品知识」），与「作品数据」
（正文/设定/素材）正交；②加载必须是**渐进披露**（描述常驻、内容按需）——技能正文是长指令，
全量塞入每轮对话=上下文噪声（Anthropic 上下文工程「curated context」原则，2026-09-18 轮已采）；
③**必须支持显式调用**（/技能名）与**模型语义匹配**两条路，且 disable 语义要能关掉自动匹配
（作者不想让模型瞎用某个技能时）。

## 三、织卷技能包格式（增量 1 基线）

### 3.1 文件形态

```
<工作区>/skills/<技能名>/SKILL.md        # 一期只支持这一个文件（纯指令）
```

- 目录名=显式调用命令名（对齐 Claude「命令名来自目录名」与 agentskills「name 须匹配目录名」）。
- <技能名> 允许中文（织卷命令面全中文，如「倒叙开篇法」；文件名/目录名=中文可行——
  织卷正文文件名即中文，文件系统层无歧义）。**校验口径**：目录名=front matter `name` 时合法；
  不一致=拒绝加载并在清单里显示为「（未校验）」？——**决定：一期不一致=该技能不生效**（严格，
  防「目录叫 A 命令却调用 B」的幻影，与 parsePatrolArgs 不静默降级同精神）。
- 一期**不开** scripts/ 与 assets/（脚本=引擎外执行面，安全与依赖面大；作者方法论以指令+现读
  references 为主）；**references/ 子目录允许**（技能正文引用 `references/xxx.md`，模型用 zj_read_doc
  现读——zsj 工具已覆盖任意相对路径，零新增）。hooks/allowed-tools/model/effort/context 等 Claude
  专有字段**一期不实现**（不解析不报错，忽略）；`license/compatibility/metadata` 保留字段忽略
  （导入导出互操作预留，见 §3.3）。

### 3.2 front matter 字段（织卷一期子集）

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 技能名（须与目录名一致；显示名+命令名） |
| `description` | 是 | 做什么+何时用，≤500 字符（含触发关键词，模型语义匹配与列表展示用） |
| `when_to_use` | 否 | 触发场景补充（追加到列表描述，计入展示截断预算） |
| `triggers` | 否 | 触发词列表（YAML 列表或空格分隔；**织卷扩展**：显式关键词匹配用，模型语义匹配之外的确定性通道） |
| `arguments` | 否 | 参数说明（如「[要点]」；命令浮层 argHint 与展开时拼装用，一期=提示文本不替换变量；`$1` 替换二期） |
| `disabled` | 否 | true=禁用（不注入清单、不参与任何匹配；设置页管理线读取它——对齐 `disable-model-invocation`+开关语义） |

正文=markdown 指令/流程（步骤、示例、边界），无格式限制；**建议 ≤3000 字符**（激活载入预算，
超限保头+注明 references 现读路径——与 zj_read_doc offset 尾注同构）。

示例（演示种子，归档 `工作区/skills/倒叙开篇法/SKILL.md`）：见 §7 冒烟种子。

### 3.3 兼容性

- 与 Agent Skills 开放标准：`name/description/when_to_use(Claude 专有)/triggers(织卷扩展)/arguments/
  disabled(织卷扩展)` —— 导出时 `triggers/arguments/disabled` 属织卷扩展字段，**纯标准客户端忽略即
  可**（规范允许未知字段？规范为 frontmatter 严格字段，多余字段在 claude.ai 上传会硬错——织卷导出
  走「标准子集」时剔扩展字段即可，导入时标准文件仅 name/description 也能工作）；一期只读不写，
  互操作面登记为设置管理增量的验收项，不阻塞运行层。

## 四、存放位置与作用域

- **一期=工作区级**：`<工作区>/skills/`（工作区=设置页「工作区」配置，D-V2-8；默认
  `~/Documents/织卷工作区`）。理由：写作方法论/流程是**作者资产**（跨项目生效，与「人物/世界观」
  的项目级相反），且不与「与保密小说严格隔离」冲突（技能=方法非内容；技能正文若引用具体项目
  内容由作者自控）。
- **项目级 `.zhijuan/skills/`（二期候选）**：跟项目走、可入 git 共享的团队/系列技能；触发条件=
  主人反馈「不同书需要不同技能集」或技能内引用项目专有术语时。登记为触发制观察项，**本期不做**。
- 扫描：主进程启动时/项目打开时读一次清单（listSkills 纯函数：递归一层目录，只认 SKILL.md）→
  缓存；设置管理增量在增删改后失效重扫。清单元数据进上下文走 §5。

## 五、注入面与触发（与线 A 交叉——主责：智能层）

### 5.1 清单注入（描述常驻，对齐 Claude「description always in context」）

- **位置**：runChat 的 system 段（envBlock 之后、buildWritingContext 之前）新增
  `【可用技能】` 块：
  ```
  【可用技能】（作者沉淀的写作方法/流程；需求匹配时说明「按<技能名>来做」，或直接输入 /技能名 调用）
  - 倒叙开篇法：从人物高光时刻落笔再回叙起因，制造悬念与代入感（触发词：倒叙/开篇）
  - …
  ```
- **预算**：新增 `SKILL_CAPS`（shared/contextCaps.ts 单一权威源，先例 WCTX_CAPS）：
  `list=每技能 description ≤120 字符（截断）+ 总清单 ≤600 字符`（≈业界 100 tokens/技能级，
  织卷清单按项目可用技能集通常个位数）；激活正文 `body=3000 字符`（对齐推荐 <5000 tokens 的口径，
  中文场景 3000 字符≈合理指令量）。超预算清单=按技能名剥离 description 只留名称（对齐 Claude
  「name-only」）；**不动**：WCTX_CAPS 八块装配、既有预算常量、引擎事件协议。
- **范围**：仅 runChat（创作对话）；**子任务/检查类不注入**（子任务=结构化检查任务、不需要作者
  方法论技能；若需「检查类技能」=二期候选，登记触发制）。runSync 不注入（同步=设定流，非创作）。
- **未打开章节**（chapterRel=null）也注入（作者在项目页问「怎么开篇」同样要用）。

### 5.2 激活（内容按需载入）

两条通道，同一注入面：

1. **显式**：`/技能名 [参数]` —— 复用 `/命令槽位`（parseCommandTrigger/filterCommandCandidates/
   insertCommand 已在 shared/commands.ts，**零新触发逻辑**）：新增 `ZYJCommand.kind='skill'` 与
   `dynamicSkills` 合并进 ALL_COMMANDS（内置优先：与内置重名时内置胜，技能仍可在列表列出并标注
   「技能」）；「发送时」主进程 matchSkill 确认 → 技能正文注入本轮（见 5.3）。
2. **模型语义/关键词**：主进程在 runChat 组装时对 `用户输入+本轮 quote` 做
   `matchSkillForInput(text)`（shared/skills.ts 纯函数）：先`triggers` 精确包含匹配（任一触发词出现
   即中，**只做关键词不做 embedding**——bge-m3 在线被动资产 2026-09-17 轮已就绪，语义匹配=二期
   候选，触发条件=关键词漏检反馈）；再回退 `description` 分词命中（≤2 条，按命中数排序取前 2，
   防一次激活一堆）。`disabled:true` 的技能不参与匹配不注入清单。
   **模型侧引导**：清单块尾注明「与需求匹配时说明按<技能名>来做」，让显式路径可被模型自己提出来
   （模型不能自行加载，它提出、作者确认=半自动；也可作者直接说触发词=全自动）。

### 5.3 激活内容注入

- 激活时：技能正文（front matter 剥离后的 markdown）作为 system 段新块
  `【技能：<名>】` 注入**本轮**用户消息之前；`arguments` 参数文本拼在块尾
  （「参数：<原文>」）提示模型按参数执行——`$1` 变量替换二期。
- **预算**：`body=3000`；超限=保头+尾注「已省略 N 字符；完整/其余部分在
  `skills/<名>/SKILL.md`，需要时 zj_read_doc 读取其子文件」。
- **重复激活**：同会话（同 projectId+技能名）已在本轮可见历史中存在→**不重复注入**，改为在清单行
  后标注「（已加载）」？——**一期简化**：织卷每轮 runChat 由渲染层携带 history（
  trimHistoryMessage 口径），技能内容作为 system 段**每轮重组**（不写历史）→ 重复激活无「第二份」
  问题，成本=每轮重新注入（`body ≤3000` 在 4.1 万装配预算内占比小，可接受）；若后续要求「仅首轮
  注入」再优化为「活跃技能记忆」{projectId+名→已注入}（登记二期候选）。
- **不为技能内容单独压缩/回退**（织卷无 auto-compaction；历史 trim 由渲染层做，技能在 system 段
  每轮重算，语义=「本轮到场的指令」——与导演板随行注入（≤2500 字，ROADMAP 2026-09-08）同型，
  一致性最好）。

## 六、与既有入口的关系（正交表）

| 入口 | 对象 | 载体 | 关系 |
|---|---|---|---|
| `/续写 /润色 /延伸`（BUILTIN_COMMANDS.template） | 通用创作动作 | 代码固化模板 | **内置**：优先于同名技能 |
| `/巡查 /导演`（FIXED_COMMANDS.action） | 固定逻辑 | 直连既有入口 | 不动；技能不支持 action 型（一期） |
| `/技能名`（新增 kind='skill'） | 作者方法论 | 用户 md 资产 | 与内置同菜单分组显示（「内置」「技能」），见线 B |
| `@引用` | 项目资产（文档内容） | 注入内容 | 正交：技能=方法不是文档；技能正文引用文档路径走 @（二期） |
| 触发词/语义自动激活 | 同上技能 | 关键词匹配 | 显式之外的补路；disabled 可关 |

冲突口径：**内置命令 > 技能**（同名时 expandCommand/matchFixedCommand 先行，技能仅在菜单列出且
标注）；技能之间重名=以目录名唯一性天然防重（同目录名不允许）；「/技能名」未匹配到=按普通消息发送
（现状行为不变）。

## 七、验收口径（增量 1 运行层）

**单测**（shared/skills.ts 纯函数 + vitest 先例）：
- parseSkillFile：合法/缺 name/description 与目录名不一致/triggers 解析（列表与空格串）/disabled
  /arguments 提示（6+ 例）
- skillListing：预算截断（description 超长→截；清单超总预算→name-only；disabled 排除）（4 例）
- matchSkillForInput：triggers 命中/描述分词命中/多命中 ≤2 排序/disabled 不参与/无命中（5 例）
- filterCommandCandidates 合并动态技能、内置优先（2 例）

**真模型探针**（scripts/skill-live.mjs，照 material-use-live 骨架）：
- 临时项目+工作区技能「倒叙开篇法」（正文步骤含「先写人物最高光一幕再回叙起因」+references）
- 场景 A：用户输入含触发词「帮我按倒叙开篇法写开头」→ 会话日志含【技能：倒叙开篇法】块
  → 模型回文体现方法（不编造、不称没听说过）
