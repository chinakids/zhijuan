# 检查自动化 · 提案收口 · 设计（2026-10-28）

> 主人反馈（原话）：「几个校验功能放的太分散且太深了，规则体检，小环，一致性，冷读，多视角。最好能放在某处统一展示。」
> 后续：「所有的检查是否能自动跑，跑完自动提案，把提案作为功能收口，然后可以在提案中配置要启用哪些功能。」

## 一、现状（为什么分散）

| 入口 | 覆盖 | 触发 | 位置 |
|---|---|---|---|
| 底部 HealthBar（盾牌/小环） | 本地 9 项（在场/时序/腐坏/缺段/档案切片/称谓发现/称谓混用/用词重复/复读） | 打开项目、保存后 3s 节流、60s 心跳、手动 | 编辑器底栏右侧 |
| Agent 面板「检查」菜单 | AI 3 项（一致性巡查 / 冷读报告 / 多视角审视） | 手动 | 右侧 Agent 区顶部 |
| AuditDrawer | 全部 12 项（下拉切换） | 由上面两处打开 | 覆盖层抽屉 |

问题：三个入口 + 两套心智（本地 vs AI）；AI 三项埋在 Agent 面板菜单里；结果看完即走，不进入待办。

## 二、目标

1. **一个入口**：编辑器工具栏「检查」（已完成）+ 底部体检状态（保留为状态指示，点击同一抽屉）。
2. **自动跑**：按配置自动运行，不用每次手动点。
3. **提案收口**：所有检查结果统一落到「提案」箱，作者只在一个地方处置（采纳 / 拒绝 / 重开）。
4. **可配置**：在提案处配置启用哪些检查、是否自动、AI 是否参与。

## 三、机制

### 3.1 检查注册表（单一权威源）

`src/shared/auditRegistry.ts`：

```ts
export type AuditLayer = 'local' | 'ai'
export interface AuditSpec {
  kind: AuditKind
  layer: AuditLayer
  title: string          // 中文全名
  cost: 'ms' | 'minutes' // 决定默认触发策略
  /** 结果能否自动转成可执行提案；false=只出提示卡 */
  proposal: 'executable' | 'advisory'
}
```

本地 9 项 `cost='ms'`，AI 3 项 `cost='minutes'`。UI 的菜单/抽屉/设置全部由注册表生成，避免三处手写列表漂移。

### 3.2 自动运行策略

| 层 | 触发 | 约束 |
|---|---|---|
| 本地 9 项 | 打开项目、保存后 3s、60s 心跳 | 已有；加「结果变化才转提案」 |
| AI 3 项 | 保存后空闲 90s，或手动；默认**关**（成本） | 串行队列、项目级锁、单次只跑启用项；失败退避 5/15/30min |

开关：`settings.auditAuto = { enabled: boolean; kinds: AuditKind[]; ai: boolean }`。
默认：`enabled=true`，`kinds=本地9项`，`ai=false`（AI 需作者显式开启，避免每章烧 token）。

### 3.3 转提案（收口核心）

新增 `source: 'audit'`（类型 + 抽屉标签「检查」）。转换规则：

1. `item.proposal` 存在（称谓类已构造 find/replace）→ 直接用。
2. `item.target` 存在 → 生成 `append` 建议卡（沿用 AuditDrawer 现有 `createProposalFor`）。
3. `presence`（在场核查）→ 生成**可执行**卡：改该章约定头 `涉及人物` 行（find=旧行，after=新行）。这是唯一能精确落盘的本地项。
4. 其余（时序/腐坏/缺段/用词重复…）→ 只出提示卡（`kind='append'`、target=大纲/审读_<项>.md），采纳=存档到审读报告，不改正文。

去重：
- 同 `target + before + after` 归一化哈希，pending 已存在则跳过（复用 `shared/proposalDup` 思路）。
- `rejected` 同款不再重提（GitHub dismiss 语义，已有 `dedupeRejectedSliceItems` 可参考）。
- 同一检查同一轮最多 N 条（默认 20），超出按 severity 截断，避免刷屏。

### 3.4 提案处配置

提案抽屉顶部加「检查设置」popover（盾牌图标）：
- 总开关：保存后自动检查并生成提案
- 分组勾选：本地规则 9 项 / AI 巡读 3 项（AI 组额外提示「每次数十秒~数分钟 + token」）
- 「立即全跑一次」按钮（串行，进度可见）

写入 `settings.auditAuto`，与设置页同一字段（单一真相源）。

### 3.5 运行与可见性

- 运行态：提案抽屉顶部一行「检查中 3/9…」，完成后 toast「检查完成：新增 4 条提案」。
- 失败：不静默——条目级错误挂 card，重试按钮。
- 日志：`app:log` 记录每轮 kind/耗时/条数，便于排查。

## 四、分阶段

| 阶段 | 范围 | 验收 |
|---|---|---|
| P1（本周） | 统一入口（已完成）+ 本地 9 项自动转提案 + 提案处开关 + 去重 | 冒烟：保存后自动出现提案；关闭开关不再生成；重复保存不重复出卡 |
| P2 | AI 3 项后台队列 + 空闲触发 + 进度/退避 | 冒烟：开启 AI 后手动全跑生成提案；中途切换项目不串 |
| P3 | 定时巡检（每日/每万字）+ 周报汇总 | 提案抽屉按来源/检查项过滤 |

## 五、风险与取舍

- **AI 成本**：默认关；开启后串行 + 空闲触发，避免打字过程中抢算力。
- **提案噪音**：只对确定性项生成可执行卡；建议型卡片归到「建议」组，可按检查项折叠。
- **误改风险**：自动卡仍是 pending，作者采纳才写盘；presence 卡的 find 用当前约定头精确匹配，漂移则拒绝并提示重跑。
- **不做**：不自动采纳任何提案（作者裁决权保留）；不在后台改正文。
